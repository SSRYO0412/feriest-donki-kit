# REDACTION — 配布用の秘匿置換の記録

このキットは社外（クライアント環境）に渡す配布物のため、`core/` `skills/` に含まれていた
**他案件の名称を匿名化した**（2026-08-11 実施・20ファイル）。

| 匿名名 | 種別 |
|---|---|
| 案件V / project-v | 映像広告案件 |
| 案件K / project-k | 店舗系案件 |
| 案件M | 動画案件 |
| 案件O | 動画案件 |
| 案件S | 動画案件 |
| 案件H | PV案件 |

実名との対応表は**このリポジトリには置かない**（置いたら匿名化の意味がない）。
対応は発注側（BEWIBE）の内部記録にのみ存在する。

## なぜ編集禁止レイヤを触ったか

`core/` `skills/` はフォークの編集禁止レイヤ（DISTRIBUTION.md 3層モデル）だが、
これは**内容の改良を upstream に集約するため**の規約であり、この置換は内容の改良ではなく
**配布時の秘匿変換**（本来 `dist_export.py` が担う処理）。手動フォークで通し忘れていたため、
配布前にここで適用した。方法論・数値・手順は一切変えていない（固有名詞のみ）。

## ★upstream から pull する人への注意

`sync_core.sh pull` 等で upstream の同名ファイルを取り込むと、**実名が復活する**。
このフォークで core/skills を更新する場合は、取り込み後に必ず再置換すること:

```bash
# 残存チェック（0件が正常）。対象語は発注側の内部記録を参照
git diff --name-only | xargs grep -l -i "<対象語>" 2>/dev/null
```

同じクライアント（PPIH）の別商材（星が見えるカーテン・0.7人前うどん 等）は
本案件の参考・過去掲載分なので**匿名化の対象外**。

## 生成器の非同梱（2026-08-11 追加）

修正即応表・在庫表の生成器（カメラ実測・軸別集計・manifest抽出）は**配布物から除いた**。
配布先の運用は事前計算済みの表を引くだけで足り、表の再生成は発注側の仕事のため。
生成器は発注側の内部管理（SSD側 02_work/kit_generators/…の記載はこの内部注記のみ）。
★PR #5〜#6 時点の git 履歴には生成器が残る。次に履歴を畳む機会があれば併せて消えるが、
残るのは分類しきい値と列名11個程度で、DBタキソノミー本体とラベリングパイプラインは元から渡していない。
