## 1. ★合格条件の上書き宣言（このフォークのみ）

**この環境には Codex がありません。** `short-video-qc/SKILL.md` の合格条件3・4は実施者を名指ししていますが、
**実施者ではなく満たすべき性質**に一般化して運用します。**master は一切変更していません。**

```
条件3  (e)そのまま残すを選んだ全区間に independent_approval あり
条件4  独立レビュー12レンズ×3ラウンド=36回 実施済み・全指摘に採用/却下+理由
条件8  ★参考突合ゲート(G90)の全項目が許容帯内            ← 新設
条件9  ★較正ハーネス(G92)の検出率が基準以上              ← 新設
```

### independent_review の要件（全て満たすものだけカウントする）

| | 要件 |
|---|---|
| ① 隔離 | 作業ログ・制作側の理由を渡さない。**成果物＋参考＋ルールのみ** |
| ② 反証 | 「否定せよ／迷ったら却下」を明示。`refuted=true` をデフォルトにする |
| ③ レンズ | 同一質問の反復ではなく**直交する観点**で分割（12レンズ） |
| ④ 反復 | 各レンズを**3ラウンド独立**に走らせ、**2/3多数決**。割れたら却下側に倒す |
| ⑤ 記録 | 生応答を証跡として保存。指摘ごとに採否と理由。`reviewer` を必ず記録 |

### ★正直に書いておくこと

**モデル多様性は回復していません。** 「同じモデルが書いてレビューすると同じ脆弱性パターンを見落とす」という
問題は、隔離やレンズ分割では埋まりません。埋まるのは**共有文脈バイアス**（自分の理由を知っているから甘くなる）の方です。
**この2つは別物なので分けて説明すること。** 残余がどれくらいかは較正ハーネス(G92)で数字にします。

## 5. 作業の型

```
[0] 修正台帳／字コンテから、やることを引く
     ↓
[1] ★実測してから動く（推測で直さない）
     「白飛び」→ 全カットの輝度≥250画素比を測って比較
     「テンポ」→ ショット尺の分布と shots_per_telop を出す
     「カメラワーク」→ 実素材のフレーム間差を測る
     「色が埋もれる」→ 背景平均色との ΔRGB（参考帯 93〜142・下限60）
     ↓
[2] カットを選ぶなら 3〜5候補をスコアリング
     内容一致45 / 寄り引き15 / 新鮮さ15 / 尺10 / 画質5 / NG−100
     「置かない・変えない」も候補に入れる
     全候補を実画で目視（★DBのラベルを信用しない）
     ↓
[3] ★独立レビュー 12レンズ × 3ラウンド = 36回（隔離・反証・多数決）
     ＋ 盲検ランキング(G91)
     ↓
[4] Premiere で実装 → 全ショットの機械検算
     ↓
[5] ★完成画素で検証（読み戻しだけで「できた」と言わない）
     ＋ 参考突合(G90) ＋ 較正ハーネス(G92)
     ↓
[6] 記録（修正台帳の行 ＋ 修正記録DB に1行）
```

## 6. 毎回やる機械検算（全部0件が正常）

```
V1の隙間/重なり ・ 同一素材同一区間の重複 ・ 全トラックの終端ずれ
MOGRTの fontTextRunLength 不一致 ・ ズームキーの inPoint 頭ズレ
設計カット点で画が変わらない ・ 設計外の画変わり
白飛び2%超のショット ・ 黒フレーム ・ 0.40秒未満のショット
```

★**差し替えのたびに「隣のクリップの頭を2F侵す」現象が起きます。**
毎回検算して戻し、戻したらそのクリップのズームキーを inPoint 基準で打ち直す。
