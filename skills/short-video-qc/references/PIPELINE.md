### G00-G02: 初期化

```json

  "type": "vertical_short",
  "no_change_limit_sec": 2.5,
  "silence_limit_sec": 0.25,
  "min_shot_sec": 0.40,
  "subject_tag_max_repeat": 2

```
- 閾値は参考動画の実測から決める。決めた根拠（参考の実測値）を同ファイルに書く。

### G10-G12: 設計証跡
- slots.json が無い制作物は「設計判断が存在しない」ため検品失格。制作側に差し戻す。
- candidates の5件には必ず「置かない/切らない/出さない」を含む。含まれていなければFAIL。
- 各候補の `tempo_impact`（採用した場合に画が変わらない秒数がどうなるか）が空ならFAIL——テンポとの往復をせずに選んだ証拠。

### G19: 通し視聴（2026-07-29 追加・陽性コントロール検証済み）

**機械ゲートが原理的に届かない「意味と知覚」の欠陥を捕まえる層。**
Antigravity CLI（agy）経由でGeminiに完成動画（またはプロキシ）を通しで視聴させる。
**音声も聴ける**（私もCodexも聴けない穴が埋まる）。

検証実績（18_v3.mov＝人間だけが見つけた欠陥入りの陽性コントロール・ブラインドで実施）:
| 欠陥 | 結果 |
|---|---|
| 撮影の裏側の会話（「後ろも汚れてるんだよね」） | ✅ 検出（NGカットの削除漏れと正しく判定） |
| 同じ後席を「綺麗」と「汚い」で語る矛盾 | ✅ 検出（秒数ペアまで正確） |
| テロップの主語と画の不一致（後席の話中に前席） | ✅ 検出 |
| 壊れたテロップ「ホ」（0.8秒） | ❌ 未検出（1fpsサンプリングでは原理的に無理） |

新規指摘の実物検証: 「エンジンもかけたりできるの」の語中折れ＋脱字＝**真陽性**／
「やっぱり安いなに」の脱字疑い＝**偽陽性**（480pプロキシでの読み間違い。実物は正しい）。

運用:
1. プロキシを作る: `ffmpeg -i <mp4> -vf "scale=480:-2,fps=15" -c:v libx264 -crf 30 -c:a aac -b:a 64k proxy.mp4`（108秒→7.8MB）
2. **絶対パス**で渡す（相対パスだと find を打とうとして権限拒否で死ぬ）
3. 質問はブラインドで（既知の欠陥を教えない）。会話の自然さ／矛盾／テロップ異常／編集ミスを聞く
4. 指摘は**候補**として扱い、全件を実物で採否判定する（テロップ文言の指摘は誤読があるため必ず原寸フレームで確認）
5. 1フレーム級の欠陥はこのゲートの守備範囲外。既存の機械ゲート＋全フレーム観察が担当

必要な設定（~/.gemini/antigravity-cli/settings.json）:
trustedWorkspaces にSSDのパス、permissions.allow に read_file(/Volumes/Extreme SSD/**) を追加。
ヘッドレスは権限プロンプトが出せないため --sandbox --dangerously-skip-permissions で走らせる
（sandboxがターミナル操作を制限するので許容。コストはGoogleサブスクのクォータ内・追加課金なし）。

### G20-G25: 観察（★MCP禁止・CLI並列のみ）

**MCPサーバはリクエストを直列化する（実測確認済み）。全数観察に `mcp__codex-cli__codex` を使ってはいけない。**
サブエージェントを何個立てても同じMCPサーバを叩くので速くならない。

```bash
# 1. 1パス抽出（2949枚で約2秒。seekを毎回やる方式は桁違いに遅い）
ffmpeg -v error -y -i <mp4> -vf "fps=30,scale=300:-2" -q:v 4 <frames>/f%05d.jpg
# 2. 20並列で全数観察
bash scripts/codex_parallel.sh <frames> <out> 20 "<動画の説明>"
# 3. ★被覆を機械照合（PASSするまでゲートは通らない）
python3 scripts/coverage_verify.py <frames> <out> --out qc/coverage_report.json
```

実測: 20並列×148枚/本で **10.8枚/秒**。98秒の動画（2949枚）が **4分33秒**、3本で約15分。
スライスは大きいほど良い（起動に約20秒かかるため、20枚/本は0.35秒/枚、148枚/本は0.093秒/枚）。

**自己申告のCOUNTは証拠にしない。** 並列ではスライスが落ちても全体は成功に見えるため、
coverage_verify で全ファイル名の列挙を照合し、欠番スライスだけ再実行する。

- Claudeの要点読みは対象を明示的に列挙してからReadする（読んだ後に`qc/claude_seen.json`へパスを追記）。
- evidence_scan.py はセッションのJSONL（transcript）を引数に取る。検品セッションの冒頭で transcript パスを控えておく。

### G26-G27: 挿入映像の検査（2026-07-29 追加）

ユーザー指摘:
> 「後々に話が出てくるはずのものが最初にきてしまっていたり、カットが重複していたりする」
> 「車のパンのうち、車体が正面から撮れていない・あまり良い絵じゃないものがある」

どちらも**全ショットを目視して初めて気づいた**類なので、毎回機械で止める。

**G26 機械検査**（`qc_inserts.py`）:
```
python3 qc_inserts.py <broll.json> <telops.json> \
    --materials qc/materials_len.json --mention-map qc/mention_map.json --near 15
```
検出するもの（全て0件が合格）:
1. 同一素材の**区間の重なり**（使い回し）
2. 同一素材の**使用回数**が上限超過（既定2回）
3. 同一素材の**再登場が近すぎる**（既定15秒。18で2.0秒差の二度出しが実在した）
4. 同一被写体タグの回数超過
5. 挿入尺が下限未満／素材の実尺超え
6. **先出し** — その被写体が話に出るより前に画が出ている

`mention_map.json` は「タグ→その話題を導入する言葉」。
言葉が違っても同じ話題を導入しているなら先出しではないので、その語を map に足す
（例: 荷室の tag に「仕事」。「仕事ですぐ使いたい」は荷室と同じ話題）。

**G27 画の良し悪し**:
機械では測れない。**使用する窓のフレームを1枚ずつ Read して**、
- 被写体が画面内に収まっているか（前後が切れていないか）
- 名指しした対象（値札・バッジ・メーター等）が実際に読めるか
- パンの途中で被写体を外していないか
を確認し、駄目な窓は `BANNED` として設計スクリプトに**理由つきで焼き込む**。
一度不採用にした窓が再び採用されないよう、設計側でも機械で弾く。

実例（18_ACTY）:
| 窓 | 判定 |
|---|---|
| IMG_6230 0.1〜1.3 | 良い（正面・ノーズ全体と値札） |
| IMG_6230 2.0〜4.0 | ★不採用（側面寄り・車体の前後が画面外） |
| IMG_6231 0.1〜1.8 | 良い（値札が大きく読める） |
| IMG_6231 1.8〜3.4 | ★不採用（前後が切れ、値札も画面外） |

### G28: テロップとカット境界の整合（2026-07-29 追加）

ユーザー指摘:
> 「冒頭がうまく検出できず、次のカットの冒頭に文字が切れて入ってしまっていることがある。
>   例えば『45万』と表示する場合、1つのカットに『45万』まで入れなければいけないのに、
>   『45』で切れてしまい、次のカットの冒頭に『万』が入ってしまっている」
> 「必ずしも発話のタイミングに合わせる必要はない。少しずらしてもいいので、
>   見た目の整合性を優先してほしい」

それまでの検査は**テロップ同士の切れ目**しか見ておらず、
テロップが**カット境界をまたぐ**ことを一切見ていなかった。
18_ACTY では61枚中32枚が境界をまたぎ、うち6件が
「数値が割れる（この金額45｜万円です）」「次カットの頭に1〜2文字だけ残る」状態だった。

```
python3 snap_telops_to_cuts.py <telops.json> <cutlist.json> --max-shift 0.40
```

判定（境界の左右に出る文字を時間で按分して調べる）:
- 数値＋助数詞が割れる（45｜万、20万｜キロ）
- 次カットの頭に残るのが2文字以下＝断片
- 次カットの頭が助詞だけになる

直し方は**この順で試す**:
1. **時刻をずらす**（上限0.40秒）… 尻を境界まで縮める／頭を境界まで送る
2. ずれが上限を超えるときだけ**カット境界で割り直す**

★順序が逆だと駄目。割り直しを先に試すと、0.1秒台の極端に短い枚が生まれる（実際に2枚出た）。

★割ってよい位置は**必ず形態素で判定する**（fugashi・テロップ生成と同じ規則）。
　文字レベルの正規表現だけで判定した最初の実装は、
　「この金額45万円です」を**「この金額4」/「5万円です」と数字の途中で割った**。

> 発話とのズレは許容する。ユーザー指示のとおり**見た目の整合性を優先**する。

### G29: 「変なところ」の検出（2026-07-29 追加）

ユーザー指摘:
> 「①一瞬だけ演者が映り込んでいるところ ②Aロールで何か変なところ
>   ③話している内容として、別にカットしちゃっていいだろうと思われるところ を検出できないか」

**この3つはどれも合否を出さない。候補を絞るだけで、良し悪しは目とCodexが決める。**

#### G29a 人の映り込み（`qc_intruder.py`）

★**自由記述の観察をgrepしてはいけない。**
「男性/人物/手/腕」で引いたら**「助手席」の「手」に反応して62/112枚が誤検出**した。
厳密な語に絞ると0件になるが、それは「人がいない」証明ではなく「書かれていない」だけ。
→ 機械は動き補正した残差で候補を絞り、Codexには**YES/NOの定型質問**を投げる
（`--prompt` が雛形を出力。自由記述を禁じているので機械で集計できる）。

★**検出器は必ず陽性の検証用クリップで当たることを確かめてから使う。**
最初の実装（時間中央値との差）は、人を0.3秒合成したクリップで**検出0件**だった。
素材がパンなので全フレームが中央値から外れ、人の分が埋もれていた（z=1.96）。
連続フレームを位相相関で位置合わせしてから引く方式に変えたら z=36.6 で明確に立った。

#### G29b 主映像の異常（`qc_aroll_anomaly.py`）

「変」を測れる症状に分解する: 手ブレ／ピンボケ／露出の段差／色の段差／画の停止。
測る範囲は**主映像が素で見えている区間だけ**（挿入で隠れている区間は対象外・0-3）。

★`--cutlist` を必ず渡す。カット境界では画が変わって当然なので、
渡さないと検出が境界だらけになる（実測で63件中51件が境界だった）。

#### G29c 内容として切ってよい区間（`qc_speech_trim.py`）

出すもの: 内容語が薄い区間／同じ言い回しの再出現／相槌だけの区間。

★**3-gramをそのまま数えない。** 機能語だけの並び（「んですけど」「になって」）が大量に出る。
内容語を1つ以上含む並びに限る。

★**切れるかどうかを先に判定する。** 削除できるのは前後に0.18秒以上の無音がある区間だけ。
実行不能な候補を並べても意味がないので `cuttable` を付けて分ける。

### G30-G31: 機械検査
- 「無音」と「発話が無い」は別物。無音検出は3本立てで裏取りする:
  ① 切れ目が無音の中にあるか ② 区間内部に無音がないか ③ 語間0.6秒以上の発話なし区間がないか
- 繋いだ結果も測る（個々の区間が基準を満たしても、繋ぎ目で残した間が合算されて基準を超える）。
- 音声認識の固有名詞は信用しない。人名・商品名・地名は該当区間を**単独で切り出して再文字起こし**し、元素材の文字起こしとも突き合わせてから確定する。訂正を当てる場合は文言を1文字ずつの語に分けて時刻を按分する（1語にまとめると表示タイミングがずれる）。

### G40: テンポ（TEMPO.md 参照）
- 中央値・平均・分あたり本数**だけ**での合否判定は禁止。
- 「1指標だけ外れたのでOK」という報告は禁止。外れた指標は必ず5段階判定にかける。

### G50-G52: Codexレビュー
- ①②はレンダー前ゲート。レンダースクリプトに存在チェックを入れる（input_sha256照合）。
- ③で指摘が出たら再レンダーが原則。再レンダー回数を惜しんで指摘を握りつぶすことを禁止。
- 指摘の「却下」には、Codexにその根拠を返answerし、応答を記録する。

### G60: 相互整合
- 修正を1つ入れるたびに G11/G30/G31/G40 を**全部再実行**する。
- 直前までPASSだった項目がFAILに転じたら衝突。decisions.json に記録し、Codexに妥当性を諮ってから再開。

### G70-G72: 採点
- 採点サブエージェントには次の3点**のみ**渡す: 完成動画の全ショットフレーム／参考動画（またはその全ショットフレーム）／採点基準。
- 制作ログ・設計意図・言い訳を渡すことを禁止（採点者を汚染するため）。
- 議論は最低1往復: 互いの減点理由を交換→再評価→合意。合意できない項目は低い方を採用。

### G80: 報告
- 報告に書く全ての「全数」「すべて」には分母/分子が自動挿入される。
- 中間報告のスケジュール（+2h, +4h…）はタスク開始時に設定する。
