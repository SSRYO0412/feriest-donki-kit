# ショート動画 検品スキル（short-video-qc）

> 出自: 2026-07-29 の重大反省9項目（Notion「★★★ 18・19制作の重大反省と再発防止 9項目」）。
> このスキルは「機械検査が全項目0件＝良い」という等号を破壊するために存在する。
> **機械検査は「壊れていない」の証明であって「良い」の証明ではない。**

## 用語（プロジェクト非依存）

| 用語 | 意味 |
|---|---|
| 主映像 | 話者・被写体を撮った本線の映像（トーク・実演） |
| 挿入映像 | 主映像の上に重ねるカット（商品・環境・ディテール） |
| 要素 | 主映像の切り位置 / 挿入映像 / テロップ / アニメーション / SE の5種 |
| 参考動画 | テンポ・テロップ・SEの文法を採る手本の動画 |
| 証跡 | ツール実行記録・Codex生応答など、私の申告に依存しない記録 |

## ★三大禁止（違反したら検品は無効）

1. **観察の捏造禁止** — 見ていないものを「見た」と書かない。「全数」と書くときは必ず分母/分子を併記。切り出した枚数≠見た枚数。
2. **自己採点禁止** — 制作した本人（このセッションのClaude）は点数を出さない。点数は採点サブエージェント×Codexの合議のみ。
3. **工程スキップ禁止** — 締切を理由に工程を省かない。間に合わない場合は品質ではなくスコープを削り、その判断はユーザーに仰ぐ。

## ★突合原則（2026-07-30新設・G03/G13/G32/G41/G53）

検品は完成品単体では原理的に検出できない欠陥クラスがある（設計と違う窓・絶対評価では良いが
参考と違うテンポ・設計値PASSだが完成品で崩れた一致度・テロップ造形の乖離）。
したがって**上流3スキルの成果物と必ず突合する**:
- **素材DB**（asset_windows v2）: 全採用窓がconfirmed行か・DB既知のNG窓と交差ゼロか（G32）。
  検品での素材起因の発見は `windows.py set` で窓DBへ還流（検品するたびDBが賢くなる）
- **参考分析**（style_profile/telop_ledger/1秒シート）: 存在と鮮度（G03）・テンポz帯（G40）・
  完成品での軸2再実測と1秒グリッド横並び（G41）・テロップpx照合（G53）
- **カット選定**（REF-DRIVEN証跡）: スロット譜・3軸スコアカード・盲検A/B記録・conflict台帳・
  fidelity_contract の存在とスキーマ（G13）
**★採点の盲検性は維持する**: 突合は機械・ClaudeのゲートG03〜G53側だけで行い、
G70採点サブエージェント／G71 Codexには設計証跡・一致度データを渡さない
（渡すと盲検が崩れて自己弁護の追認になる。3軸評価の盲検分離と同じ構造）。

## ★能力宣言（検品者の限界を先に明示する）

- Claudeにできること: **測る**（尺・波形数値・語の照合・フレーム差分）、**静止画を枚数明示で読む**
- Claudeにできないこと: **聴く**、**動画を通して観る**、**リズムを時間の中で感じる**
- Codex（gpt-5.5）にできること: 画像ディレクトリの**全数読解**（丸投げ方式・実測済み）、敵対的レビュー、独立採点
- Codexにもできないこと: **聴く**（音は測定と再文字起こしでしか扱えない）
- したがって「音の検品」と表現してよいのは①波形実測 ②完成音声の再文字起こし照合 の2つだけ。それ以外の表現は禁止。

## ★QCプロファイル（2026-08-10 新設・黙って削る誘因を消す）

フル検品を量産の全本に掛けるのは実行不能で、実行不能なルールは黙殺される（9項目の真因）。
削り方を**事前にユーザー承認された正規プロファイル**として gates.json `qc_profile` に契約する。

| プロファイル | 適用 | 内容 |
|---|---|---|
| **FULL**（既定） | 初号機・新様式・納品前最終 | 本書の全工程 Phase 0〜8 |
| **DELTA** | シリーズ2本目以降（様式・素材群・参考が初号機と同一のときのみ） | 機械検査は全数（Phase 0/1/3/6は削らない）＋Phase 2観察は**変更点まわりのみ**全数目視＋`sample_every_n` 本に1本は FULL＋Phase 7 合議採点は抜き取り本のみ |
| **TRIAL** | 社内試作・方向確認 | 機械ゲート＋G19視聴のみ。**報告見出しに「納品不可」固定**（make_report がラベルを外せない） |

- 選択は**案件開始時にユーザー承認**し `qc_profile.approved_by / approved_at` に記録。
  空のまま DELTA/TRIAL で走ることは許されない（＝黙殺ではなく契約）
- **三大禁止は全プロファイル共通で有効**。プロファイルは「見る範囲の契約」であり
  工程スキップの免罪符ではない（DELTAでも見た範囲の分母/分子併記は必須）
- シリーズ途中で様式・素材群・参考が変わったら、その本は FULL に戻す（判定はユーザーに仰ぐ）

## 検品の全工程（省略不可・順序固定）

詳細手順は `references/PIPELINE.md`、データ形式は `references/SCHEMAS.md`、
Codexの呼び方は `references/CODEX.md` を必ず読むこと。

```
Phase 0  ゲート初期化      gates.json 生成・参考動画ハッシュ照合・能力宣言
                           ＋★G03 参照資産の存在・鮮度確認（style_profile/telop_ledger/1秒シート）
Phase 1  前提物の検査      設計証跡（スロット表・5候補スコア・decisions）の存在と整合
                           ＋★G13 参照駆動証跡（スロット譜・3軸スコアカード・盲検A/B・conflict台帳）
Phase 2  観察（全数目視）  Codex CLI 20並列で全フレーム＋Claude要点読み。被覆照合と証跡突合で捏造を機械検出
Phase 3  機械検査          尺・黒フレーム・無音・語切断・同期・画が変わらない秒数
                           ＋★G32 使用窓のDB突合（confirmed行か・DB既知NG窓と交差0・還流記録）
Phase 4  テンポ5段階判定   実測→目視→妥当性→代替候補→5択（references/TEMPO.md）
                           ★参照駆動案件は絶対帯でなくstyle_profileのz帯を優先
                           ＋★G41 完成品での軸2再実測（リズムz値・肝TOP3・1秒グリッド横並び[R6]）
Phase 5  Codex敵対的レビュー 3対象（設計案/テロップ/完成全フレーム）・採用/却下を全件記録
                           ＋★G53 テロップpx照合（measure_telop_px×telop_ledger・telop_mode=premiere時）
Phase 6  相互整合チェック   1つ直したら全ルールを測り直す。衝突は記録＋Codex承認
Phase 7  採点（合議制）     採点サブエージェント×Codexの独立採点→議論→合意
```

### Phase 0 — ゲート初期化

1. `references/gates.template.json` をプロジェクトの `qc/gates.json` にコピー
2. 参考動画の `sha256` を実測し、目標値ファイルの `source_video_sha256` と照合。**不一致なら停止**（数値の流用禁止）
3. 参考の全数分析の存在を確認（二形式対応・2026-07-30）: 旧形式=`ref_telop_grammar.json`/`ref_cut_grammar.json` **または** TIMELINE-SHEET形式=`style_profile.json`+`telop_ledger.json`+1秒シート。**どちらも無ければ検品不可**——「参考準拠」を検証する基準が無いため
4. 動画種別（縦型ショート/横型/長尺）を宣言。種別ごとの閾値（例: 画が変わらない秒数の上限）はここで確定する

### Phase 1 — 前提物の検査（設計証跡）

検品対象は完成動画だけではない。**設計判断の証跡**が揃っていなければ検品失格。

- `slots.json`: 弧のビートごとに「ここで何が必要か」が5要素すべてについて定義されているか
- 各スロットに `candidates`（**5件必須**・「置かない/切らない/出さない」を必ず含む）、各候補の `score` / `tempo_impact` / `seen`（見た画像パス）/ `selected` / `why` が揃っているか。**1つでも欠ければFAIL**
- `decisions.json`: ルール衝突の記録。空でもファイルは必須
- 挿入映像の検算は「同一開始点」ではなく「**同一被写体タグの出現回数**」で行う（開始点をずらしただけの画は目には同じ）。規定回数超過でFAIL
- 占有率・密度などの統計は**結果として記録する値**であり、目標として本数を増減した形跡（占有率のためだけの追加）があればFAIL

### Phase 2 — 観察（全数目視・捏造の機械検出）

対象: 全素材の全時間窓（0.1秒刻み）／完成動画の**全フレーム**／テロップ画像の**全枚数**／アニメーションの全フレーム／SEの全発。

- **Codex（★CLI 20並列・MCP禁止）**: `scripts/codex_parallel.sh` で `codex exec` をバックグラウンド並列起動する。
  **`mcp__codex-cli__codex` はリクエストを直列化するため全数観察には使えない**（実測確認済み。サブエージェントを立てても同じサーバを叩くので無意味）。
  実測 10.8枚/秒 — 98秒の動画の全2949フレームが4分33秒、3本で約15分。返答は生のまま `qc/codex_view/<対象>/` に保存
- **Claude（要点読み）**: ショット境界の前後2フレーム、テロップ出現・消滅の前後2フレーム、Codexが指摘した箇所を1枚ずつRead
- **被覆の機械検証**: `scripts/coverage_verify.py` でCodex返答本文に対象ファイル名が**全数列挙**されているか照合。
  欠番があればそのスライス名が出るので**再実行して再照合**。PASSするまでゲートは通らない。
  ★並列ではスライスが落ちても「他が成功したので全体成功」に見えるため、自己申告のCOUNTは証拠にしない
- **捏造の機械検証**: `scripts/evidence_scan.py` でセッション記録から実際にReadした画像を抽出し、ラベル・候補・スコアの `seen` と突合。不一致1件でFAIL
- 見ていない時間窓は `未確認` と明示。**未確認の区間を根拠にした判定は無効**

### Phase 3 — 機械検査（すべて0件が基準）

`scripts/qc_machine.py` で完成動画を全フレーム走査:

- 尺が設計値と一致（±1フレーム）
- 黒フレーム 0件 / 孤立フレーム 0件
- 0.25秒以上の無音 0件（★詰める側のしきい値は検品側と必ず一致させること）
- 音声と映像の尺差 0.000秒
- **語の切断 0件**: 完成音声を再文字起こしし、テロップ文言と照合。食い違いは**推測で直さず、その区間だけ切り出して単独で文字起こしし直して**確定（音声認識は固有名詞を捏造・誤字する。人名・商品名は必ず単独切り出しで裏取り）
- テロップ: 幅超え0件 / 1〜2文字0件 / 尺0.2秒未満0件 / 0.5秒以上の空白0件 / 表示時刻と発話の同期ズレ0件
- **画が実質変わっていない秒数**: フレーム差分で全区間実測（挿入映像を跨いでも被写体が同じなら「変わっていない」と数える）。種別上限（縦型ショート暫定2.5秒）超えの区間を列挙 → Phase 4 へ

### Phase 4 — テンポ5段階判定

**中央値1つでの合否判定は禁止。** `references/TEMPO.md` の5段階を、Phase 3で列挙された全区間に適用:

① 機械で実測（形の照合＝位置ごとのショット尺・テロップ密度・SE密度の推移）
② 目視で確認（Codex＋Claude両方。数値で別カットでも目には同じ画がある）
③ 妥当性判定（動画種別／内容＝実演は長く許容・スペック提示は短く／前後の意味の繋がり／テロップとの関係）
④ 妥当でなければ他素材の全時間窓から5候補スコアリング
⑤ 候補が無ければ5択を全部スコアして選ぶ: (a)ズーム/クロップで画を作る (b)主映像に戻す (c)発話を削って尺を詰める (d)前後の配分を変える (e)そのまま残す＝**理由記録＋Codex承認必須**

### Phase 5 — Codex敵対的レビュー（3対象・省略不可）

`references/CODEX.md` の呼び方（**gpt-5.5固定**・丸投げ方式）で:

1. **設計案**: 全スロットの候補とスコア＋候補フレームのディレクトリ → 「このスコアは妥当か。より良い候補を見落としていないか」
2. **テロップ**: 全テロップ画像＋対応する発話 → 「区切り・改行・意味のまとまり・強調の当て方は参考の文法に合っているか」
3. **完成動画の全フレーム**: ディレクトリ丸投げ → 「同じ画の繰り返し・テロップと画の不一致・カット順の違和感を敵対的に列挙」

- 1と2は**レンダー前**。3はレンダー後のため、**指摘が出たら必ず再レンダーする前提**で工程を組む
- 全指摘に `採用/却下＋理由` を記録。却下にもCodexへの返答を残す（握りつぶし禁止）
- レンダースクリプトは `codex_review_*.json` の存在と `input_sha256` の一致を検査し、無い/古ければ**実行しない**

### Phase 6 — 相互整合チェック

1つの修正を入れるたびに、**全ルールの合格条件を測り直す**。

- 直前まで合格していた項目が不合格に転じたら「衝突」と判定して停止
- `decisions.json` に `rule_kept` / `rules_affected` / `tradeoff` / `reason` / `codex_approval` を記録しなければ再開不可
- 典型例（実際に起きた衝突）: 「占有率を合わせる」→「同一素材の使い回し禁止」を破る／「短ショット0件」→「言葉を言い切る」と衝突

### Phase 7 — 採点（合議制・自己採点禁止）

- **採点サブエージェント**: 作業ログを見せず、①完成動画の全ショットフレーム ②参考動画 ③採点基準 の3点だけを渡して独立採点
- **Codex**: 同じ3点で独立採点
- 食い違った項目は互いの指摘を渡して**議論・再評価**させ、合意点を `qc/scoring/final.json` に保存
- 制作者Claudeは根拠（測定値・証跡）を提出するだけ。**点数を書く・変える・丸めることを禁止**

### Phase 8 — 報告

`scripts/make_report.py` が gates.json と証跡ファイルから自動生成:

- `未実施: N件` を必ず表示。**N>0 なら見出しは「未完了」固定**（「完了」の語を出力できない）
- 点数は `scoring/final.json` が存在するときのみテンプレが埋める。手書きの数値は禁止
- 「全数」と書く箇所はテンプレが分母/分子を自動挿入する
- 長時間タスクは中間報告を時刻でスケジュール（開始+2h, +4h…）し、毎回未実施一覧を貼る

## 検品の合格条件（全て満たして初めて「検品通過」）

1. Phase 0〜8 の証跡ファイルが全て存在（gates.json のチェックが全PASS）
2. 機械検査 全項目0件
3. テンポ判定で (e)そのまま残す を選んだ全区間に codex_approval あり
4. Codexレビュー3対象すべて実施済み・全指摘に採用/却下記録あり
5. 相互整合チェックで未解決の衝突0件
6. 合議採点 `scoring/final.json` が存在し、合意スコアが基準（既定95点）以上
7. evidence_scan / coverage_check の突合が全PASS（捏造0件）

1つでも欠ければ「検品通過」と報告してはならない。ユーザーへは欠けている項目を名指しで報告する。
