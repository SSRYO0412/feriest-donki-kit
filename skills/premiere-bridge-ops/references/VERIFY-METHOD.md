# 検証の工程（映像を自動操作したときに「できた」と言ってよい条件）

Premiere/AE に限らず使える。**この工程を飛ばした報告は無効**とする。

---

## ★★★ 大原則

**①スクリプトの戻り値 ②アプリからの読み戻し だけで「適用済み」と報告してはならない。**
**③書き出した実ファイルの画素/波形で測るまで完了と言わない。**

**なぜ読み戻しで気づけないか（本質）**:
`getKeys()` も `getValueAtTime()` も **自分が書いた座標系で返す**。
書き込みと読み出しが同じ誤りを共有するので、**照合は必ず通ってしまう**。
**同じAPIで書いて同じAPIで読む検算は、座標系・単位の誤りを原理的に検出できない。**

実例: テロップ46枚にアニメーションを付け、APIで読み戻して80枚全数「設計どおり」を確認し
レンダーまで出したが、**完成MP4では全く効いていなかった**（キーフレームの時間基準が
クリップの `inPoint`＝静止画では3600秒だったため）。

## 1. 書き出さずに測る — `sourceRectAtTime`

**AEのテキストレイヤーなら、書き出さなくても「効いているか」を機械で測れる。**
`sourceRectAtTime(t, false)` は**レイアウトエンジンが返す実寸**であって、
自分が書いた値の読み戻しではない。**だから独立した検算になる。**

| 見たいこと | 測り方 | 判定 |
|---|---|---|
| 縁が描かれたか | 線幅 0 と 20 で `width` を比較 | 差が `2×20` 出れば効いている |
| 書体が変わったか | 同じ文字列で全レイヤーの `width` | **全部違う値**になるはず。同値なら代替されている |
| 文字が出ているか | `width` が `0.0` でないか | 0 なら**空**（式が `undefined` を返している） |
| 出し分けができているか | 各レイヤーの `Opacity.valueAtTime` | 見えているのが1枚だけか |
| 式が壊れていないか | 全プロパティを再帰し `expressionError` | **0件か** |

```javascript
var errs=0, chk=0;
function walk(g,path){ for(var i=1;i<=g.numProperties;i++){ var p=g.property(i);
  if(p.numProperties!==undefined && p.numProperties>0) walk(p, path+"/"+p.name);
  if(p.expression!==undefined && p.expression!==""){ chk++;
    if(p.expressionError && p.expressionError!=="") { errs++; log("★"+path+"/"+p.name); } } } }
for(var L=1;L<=c.numLayers;L++) walk(c.layer(L), c.layer(L).name);
```

## 2. ★★★ 測定器の盲点を疑う（「効いていない」の8割はこれ）

**「効いていない」という測定結果が出たら、その結論を採用する前に、
まず「その測定器がその変化を見られるか」を確かめる。**

### 実際に踏んだ（2026-08-09 Feriest でさらに4件・計6件）

**① バウンディングボックスは両端の文字でしか動かない**
2〜4文字目を80%拡大しても `sourceRectAtTime` の値が1ミリも動かず「★効かない」と出た。
**動いていなかったのは測定器の方**だった。外形は左右の端の文字で決まるので、
**真ん中だけの変化は原理的に見えない。**

正しい測り方（本文7文字・拡大80%の実測）:

| 強調する範囲 | 左端 | 右端 | |
|---|---|---|---|
| 先頭1文字だけ | **+72.6** | 0.0 | ✅ |
| 末尾1文字だけ | 0.0 | **+81.4** | ✅ |
| 中央のみ | 0.0 | 0.0 | ✅ **変わらないのが正** |
| 全部 | +72.6 | +81.4 | ✅ |

**② 黒背景に黒フチ**
白文字＋黒フチのテロップを何も敷いていないタイムラインに置いた。
背景も黒なので、**フチは正しく出ているのに見えなかった。**
これを「スクリプトが効いていない」と誤判定し、レンダラーの非互換を疑って
5方式の診断テンプレートまで作った。**結果は「最初から出ていた」。**

**③ 1フレームだけ見て「出ていない」と誤断定**（2026-08-09）
c04 の1フレームだけを見て「ロックアップが出ていない」と結論した。実際は背景が白飛びした
ピザで白文字が埋もれていただけ。c01 では出ていた。**別の時刻・別のカットでも確かめる。**

**④ 測定窓が狭くて「はみ出し」を誤検出**（2026-08-09）
テロップの幅測定の窓が狭く「画面幅はみ出し」と出たが、実際は2行化が効いていて収まっていた。

**⑤ 倍率の測定窓に等倍の帯を含めて「ズームが効いていない」と誤判定**（2026-08-09）
測定領域に等倍のテロップ帯が混ざり、平均倍率が薄まった。テロップ帯を除いたら設計と一致した。
**測るものだけが窓に入っているかを先に確かめる。**

**⑥ 色マスクが被写体に汚染される**（2026-08-09）
テロップ色の機械マスクが食材の色（`#E4AF4A`）を高さ400〜800pxで拾った。
**色と役割の裁定は帯を並べた目視**（TELOP-CRAFT [2-0] と同じ原則）。

### 手順にすると

1. その測定器で**変化が出るはずの条件**を1つ作り、**実際に出ることを確かめる**
2. 出なければ**測定器を替える**（外形→端の位置、色→書き出して比較、など）
3. 配色・背景・不透明度など**見えなくしている要因**を潰す
4. そこまでやってから、はじめてアプリ側の非互換を疑う

## 3. 書き出した実ファイルで判定する（ffmpeg）

**変えたはずのものが本当にレンダーに乗ったか**は、2本書き出して比べれば機械で分かる。

```bash
ffmpeg -hide_banner -i a.mov -i b.mov -lavfi ssim -f null - 2>&1 | grep -i "SSIM" | tail -1
ffmpeg -hide_banner -i a.mov -i b.mov -lavfi psnr -f null - 2>&1 | grep -i "PSNR" | tail -1
```

★**`-v error` を付けると出力ごと消える。** `-hide_banner` にして `grep` で拾う。
★**完全一致は `SSIM All:1.000000` / `PSNR average:inf`。** そうでなければ差がある。

```bash
bash scripts/ssim_check.sh a.mov b.mov        # 同梱。判定文つきで出る
```

### 実績

| 何を確かめたか | SSIM | 結論 |
|---|---|---|
| MOGRTの**書体**を差し替えた2本 | 0.9816 | レンダーに反映されている |
| MOGRTの**サイズ**を差し替えた2本 | 0.9524 | 反映されている |
| **分割2クリップ vs 1クリップ**（同じ行） | **0.999722** | ほぼ完全に再現できている |
| （対照）**20pxずらした**版 vs 1クリップ | 0.987369 | 20pxの誤差は検出できる |

## 4. ★★★ 対照実験を必ず置く

**「差が出た／出ない」を言う前に、出るはずの条件で本当に出るかを測る。**

`0.9997` という数字は、**`20px ずらした対照が 0.9874`** だと分かって初めて意味を持つ。
対照が無ければ「SSIMが高いのは画面の大半が背景だからでは？」に答えられない。

- **差が出るはずの条件**（わざと間違えた版）を1本作る
- **差が出ないはずの条件**（何も変えていない版）も作れるなら作る
- 3本を並べて、**測定の感度**を示してから本題の数字を出す

## 5. 候補が複数あるときは、診断物を1本作って1回で決着させる

**推測で1つずつ潰さない。** ユーザーの目視は貴重なので、**1回の確認で原因が特定できる形**にする。

縁取りが出ない原因を切り分けたときの実例（**方式ドロップダウン1つ**で5案を切り替え）:

| 方式 | 出た場合に分かること |
|---|---|
| A アニメーター＋範囲セレクター＋式 | 現行方式がそのまま使える |
| B アニメーター（範囲なし）＋式 | セレクターが原因だった |
| C アニメーター＋**固定値**（式なし） | **式**が解釈されていない |
| D 文字パネルに**焼き込み** | アニメーター自体が解釈されていない |
| E プリコンプ＋塗り＋チョーカーで**膨張** | 文字の線を諦めて効果で作る |

★診断物には**必ず「絶対に見えるはずの対照」**（この例ではD）を入れる。
★**色は背景と絶対にぶつからないもの**にする（この例では赤）。

## 6. ユーザーに絵を見てもらうときの渡し方

**絵の最終判断はユーザーがする。こちらは判定しない。** 渡すときは4点を添える。

1. **どこにあるか** — シーケンス名・時間・ファイルパス
2. **何が入っているか** — クリップごとの設定を表で
3. **どこを見てほしいか** — **1〜3点に絞る**
4. **その結果でどう分岐するか** — 出た場合／出ない場合に次に何をするか

★**配置まで済ませてから渡す。**「読み込んでください」で止めない。
★**こちらの機械検算の結果を先に示す。** 何が既に確認済みで、何が未確認かを明らかにする。
★検証のためだけに書き出したものは、**渡して止まる**（こちらで良し悪しを言わない）。

## 7. 報告のしかた

- **見た枚数は分母/分子を併記する。** サンプリングしたなら「した」と書く
- **通らなかった項目は隠さない。** 「◯件中エラー△件」の形で出す
- **設計どおり反応しないのが正しい項目**（固定値・色だけ変える方式など）は、
  **そう明記してから数字を出す**。でないと自分の検算に嘘をつかれる
