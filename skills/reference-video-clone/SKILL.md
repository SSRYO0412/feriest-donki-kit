# 参考動画 完コピ編集スキル（情緒分析 → 5次元編集 → 多重検証）

> ★このスキルの2用法（2026-07-30明確化）:
> ①**フル完コピ**: Phase 0〜5 をこのスキルで完結（Remotion合成まで）。
> ②**分析のみ提供（+C修飾）**: short-video-pipeline 系の案件では、本スキルからは
> `references/TIMELINE-SHEET.md`（[R0]〜[R6]・1秒シート→style_profile.json）だけを回し、
> 選定以降は short-video-cut-craft REF-DRIVEN-SELECTION（3軸評価）→ pipeline のDAGへ渡す。
> ②では Phase 3〜5（Remotion編集）は使わない。

> ★★★**カット編集を行うなら、着手前に `references/CUT-QC-RULES.md` を必ず全文読む**。読まずに着手してはならない。
> カット選定（全素材×全時間窓のフレーム単位ラベル→3〜5候補のスコアリング→Codex敵対レビュー）、
> 検品（毎回「全フレーム目視・音声波形・ルール再読・過去ミス全チェック」の4点必須／3回に1回は全面チェック）、
> 修正ループ（95点超えるまで反復）、履歴管理（py上書き禁止・Notion毎回）の正本。

> ★横断原則（実測主義・サブエージェント検証の鉄則・目視の作法・並列安全策・承認ゲート）は `references/PRINCIPLES.md` を必ず適用する（正本: `~/.claude/skills/_video-core/`）。
> ★動画制作後に継続修正が入る案件では `video-revision-db-workflow` を併用し、台本/カット/素材使用/修正指示/レンダーpy/QAログをNotionに残す。

## Notion管理がある案件

Notionの映像管理DBがある場合、編集前に `修正指示DB`、`動画台帳`、`カット台帳`、`素材DB`、`素材使用DB` を読む。新規レンダーは完成MP4だけでなく、生成に使ったpy、edl/video.json、素材パス、音声/BGMソース、QA結果を `レンダーpy管理DB` と `QAログDB` に記録する。修正指示は削除せず、完了後にステータスと対応後メモを更新する。

参考動画の編集を **情緒の弧**として実測・資産化し、別素材を **5次元**（テロップ/カット/SE/間/フレーミング）で完コピし、**4層**で検証する。
**正確性 > 効率性**。各フェーズに承認ゲート。推測で進めない。

## ★核心思想（これを外すと失敗する）
- **強調は単語の種類で決めない。その文が情緒の弧のどこ（山/谷/上り）にいるかで決める。** 「OK→緑/NG→赤」のような語カテゴリの機械対応は**浅い・禁止**（実際にユーザーから却下された反面教師）。
- **情緒を読むのは毎回 editorial-analyst（私=Claude判断）。型と語彙はファイル資産化**。感情判断をコードのif文に埋めない。コードは「私が付けた明示ラベルを描画するだけ」。
- **1本の情緒の弧を背骨に、テロップ/カット/SE/間/フレーミングを"トラック"としてぶら下げる**。各次元は「情緒→その次元の演出」を演出プリミティブで書く（`references/SCHEMA.md`）。
- **色は単語でなく体温**。判定/オチは互いに**描き分ける**（同じ不採用でもバッサリと優しい否定は処理が逆）。
- **ビジュアル（フォント/色/デザイン）はオリジナルを混ぜない・完全一致が原則**。参考動画と同じ書体・色・サイズ・装飾を使う。近似は「実測できず・入手不可」の最終手段のみで、その場合も視覚的に区別がつかないレベルまで詰める（`references/telop-analysis-methodology.md` 12節）。
- **検証は1回で終わらせない**。Phase 5 の全層・全項目が100点（WARN/FAILゼロ）になるまで、検証→修正→再検証を回数無制限で繰り返す（`references/verification.md`）。
- **時間軸の編集量（テンポ）は見た目と同格の完コピ対象**。カット密度・SE密度・テロップ更新頻度・変速を参考から実測し、出力を `verify_tempo.py` で参考の±30%以内に収める。**静的な見た目が一致していてもテンポが乖離すれば「編集されていない」印象になり納品不可**（実証: カット/分が参考の1/5・31秒ノーカット・SE 6発vs28発の出力がクライアントに差し戻された。分析はカット語彙を知っていたのにEDL設計で捨てられていた）。

## 全体像
```
[Phase 0] 環境準備（venv / node@22 / 依存）
[Phase 1] 参考動画の情緒分析 → arc.json + tone-library更新（型と語彙の抽出）
[Phase 2] 元素材の正確な文字起こし（局所窓・VADオフ・文単位）→ words.json + 台本
[Phase 3] 素材の情緒設計 → arc.json（演出プリミティブ）→ edl.json ※Claude authoring・承認ゲート
[Phase 4] 編集（ffmpeg切出し → Remotion合成: テロップ/SE/フレーミング）→ final.mp4
[Phase 5] 4層検証（次元内∧次元間∧情緒整合∧多重サンプリング）
```

## 素材が無いとき（AI生成 → Remotion）
実写footageが無ければ素材をAIで作って合成（詳細 `references/asset-generation.md`）:
- シーン/背景=**Codex `image_gen`（`model:"gpt-5.5"`・APIキー不要）** or nanobanana / 動く実写=AI動画(fal.ai Kling)
- **日本語テロップはAI画像生成しない**（漢字崩れ）→ Pillow/Remotionネイティブ。Codex自身もそうフォールバックする
- 静止画→Remotionの`<Img>`+Ken Burnsで寄り引き（固定実写の謎ズーム問題が起きない）
- 顔出しナシ系は素材ナシでほぼ完全再現／実写リアクション系は人物ベース(実写orAI動画)必須

## I/O ファイル構成（規約・詳細は `references/file-structure.md`）

- `references/<参考名>/` … 参考分析（再利用資産）: in/source.mp4 → out/arc.json・analysis.md ＋ ルート `tone-library.md` 追記
- `jobs/<案件名>/` … 素材1本→動画1本: in/source.mov・brief.md → work/(words/script/arc/edl/clips/video.json) → out/final.mp4・verify/

## Phase 1 — 参考動画の情緒分析（型と語彙の抽出）
1. `scripts/transcribe_ref.py <ref> ref.words.json` で文字起こし（文単位）。
2. **editorial-analyst（分析モード）** に文単位トランスクリプト＋`references/tone-library.md` を渡し、情緒の弧（背骨）を確定。**視聴者ペルソナと関心軸も1〜3行で言語化**して arc.json meta に残す（素材選出の判定基準）。
3. **5 specialist** が各次元を実測しながら注釈（`references/SCHEMA.md` の演出プリミティブで）。実測ツール:
   - テロップ: `segment_telops.py`（遷移検出+フル解像度抽出）→ `measure_form.py`（色/サイズ。**帽子・木目・UIの混入に注意、必ず目視確定**）→ `montage.py`（コンタクトシート目視）
   - カット/間: `detect_shots.py`（ショット境界・テンポ。**複数閾値スイープ既定**＝単一閾値0.30はトーキングヘッドのジャンプカットを4割取りこぼす実証あり）
   - SE: `analyze_se_motion.py se`（BGM安全・温存パターン）
   - フレーミング: `measure_framing.py`（寄り引きの代理・パンチイン）※発火ゲート（下記）
4. **synthesizer** が統合し、`tone-library.md` に新トーン/語彙を追記（**育てる資産・流用でなく毎回再測定**）。
5. **★判断文法の抽出（正解編集の判断ログ化）**: 参考（および同シリーズに合格済み編集があればそれも）の**全カット・全テロップを1つずつ「状況→判断」として記録**する。集計値（cuts/分）は粗すぎ、タイムライン完コピは素材特異的すぎるので、その中間の**移植可能な文法**を数値付きで抜く:
   - カット: 切り位置は語尾の何フレーム後か／何を詰めたか（間・フィラーの長さ）／何を保持したか（判定後リアクション秒数・表情の動き）／ズーム切替の動機（判定語頭・キー句・切り返し）／ショット長×内容種別（説明/オチ/リアクション）の対応
   - テロップ: 出現アニメの実体（立ち上がりフレーム数・popの弾み）／発話との同期オフセット／**表示単位（意味のまとまりの区切り方を全数写経して規則化）**／行の増え方・縮退の動き
   - この文法が素材をまたぐシリーズ資産になる（新素材の設計は文法から組む）
6. 出力: `arc.json`（参考の情緒の弧＋全トラック＋実測語彙）＋判断文法。

## Phase 2 — 元素材の正確な文字起こし
- **映像内蔵音声**で文字起こし（別撮りは同期ズレで使わない）。
- 全体像は `transcribe.py`、**EDL時刻は full pass を信用せず** `window_transcribe.py <src> words.json 0-30 ...`（局所窓・VADオフ）で正確な単語境界を取る（理由は pipeline-notes.md）。
- `make_script.py words.json` で**文単位スクリプト**（情緒設計の入力）。

## Phase 3 — 素材の情緒設計（★Claude authoring・承認ゲート）
- **editorial-analyst（設計モード）** に素材の文単位スクリプト＋`tone-library.md` を渡し、素材の情緒の弧を作る → 5 specialist が演出プリミティブを割当 → synthesizer 統合 → `arc.json`。
- arc.json を **edl.json に落とす**（どの発話を使うか/テロップ文言/各次元の演出）。編集判断は私が直接 authoring（別LLM API不要・`references/editorial-template.md`）。
- **★カット選出（どの発話を有りとするか）は `editorial-template.md`「カット選出ルール12項」に従う**: ビート数パリティ（弧が足りなければQ&A/掛け合いを間奏ビートに昇格）・1ブロック尺予算・機能カバレッジ（CTA発話を探す）・採用優先度〈判定/断言/数字/固有名詞〉・質問は核だけ・定型情報はカード化・グダグダは参考準拠（整った編集なら捨てる/生っぽい編集なら残す）・採否は相対評価。選出直後にブロック数/尺分布を参考と数値比較。
- **★EDLのカット粒度は参考の実測テンポに合わせる（「1文=1クリップ」「1役割=1クリップ」禁止）**: 設計後に「クリップ数÷合計尺」を参考の cuts/min と比べ、±30%を外れたら設計し直す。**参考の最長ショットを超えるスパンは `圧縮ジャンプ`（文節境界で間・フィラー・冗長を0.2〜0.5秒単位で落として複数クリップに分割）で必ず刻む**。「一文の連続した思考だから中略せず全体採用」は反面教師（17.8秒撮って出し→納品差し戻しの実例）。
- **★EDL設計直後に `check_budget.py` で尺予算を機械照合する（必須）**: 総尺=Σ(out−in)/speed を承認済みベンチマーク（クライアント合格版等）±15%と比較。実証: 暗算設計の初版EDLが目標105sのつもりで実測160.7s(+52%)になり、build後に10クリップ削除の再設計になった。超過時は等速の長尺クリップから削減材料が列挙される
- **★EDLは `snap_edl.py` を通過してからしか cut.py に渡さない（手打ち in/out の直接使用は禁止）**: 語頭保護・語尾+0.10s・孤児モーラ吸収（上限2トークン/0.45s）・隣接クランプを機械保証し、`--check` で監査。実証: 手打ちEDLで「お待ちしてま|す」「営業しましょ|う」「です|か」等の最終モーラ切れが7箇所発生し「セリフをぶった斬っている」と差し戻された。文字起こし目視では最終モーラ切れは検出できない（whisperは切れた語も報告する）。whisperのスミア帯（語が数秒に引き伸びる区間）は音量実測で裏取りして nosnap 固定。
- **★`carry_pauses.py` を snap 後の必須工程にする（ポーズ持ち越し）**: ギャップ≤0.8s(呼吸内ポーズ)または尻が継続形(とか/て/けど…)なら「話者の間」を削除禁止＝前クリップのoutを次inの直前まで自動延長。完結形で終わる0.8〜1.2sは文境界の正常ジャンプカットとして維持(テンポ装置)。実証: 列挙イントネーション（〜とか↗）直後の0.68sポーズ削除が「切れて聞こえる」原因だった。詰めは削除でなく変速で行う（ポーズも変速で比例短縮される）。抑揚の継続はF0ベースの `check_prosody.py`（WARN級・精読のトリアージ入力）でも補助検査
- **カット点は語境界±0.15秒**にスナップ（合格実例の実測: 29カット中27が語境界±0.25s以内・中央値0.09s）。
- **変速（スピードランプ）を authoring する**: pace=`詰め` の説明/列挙モノローグは clip に `"speed": 1.3〜1.5`（ピッチ保持倍速・cut.py/build.py 対応済み）、**判定/オチ/溜めは必ず等速**。合格実例の実測は説明1.5倍速・オチ1.07倍（=「説明は流す・オチは聴かせる」）。★**変速は「区間単位」で平滑に**: 同一モノローグ内の隣接クリップは同じ speed に揃える。クリップごとに1.0→1.4→1.2→1.35と細かく変えると声のリズムが2秒ごとに伸び縮みしてガクつく（v2差し戻しの一因）。速度が変わってよいのは意味の区間の境目（説明→判定等）だけ。
- **構成は素材の時系列に縛られない**: 参考がコールドオープン（判定など山から入り、文脈は後出し）・弧間の変化球（Q&A/掛け合い）・CTA締めを持つならその構成をクローンする。素材が単調な場合も再構成を能動的に設計し、承認ゲートで提示する。
- **arc.json と edl.json をユーザーに提示して承認を得てから編集**（カット選定はユーザーの領分）。

## Phase 4 — 編集（5次元の適用）
1. `cut.py <proj>` … edl.json から ffmpeg 切出し（HDR tonemap・autorotate）。
2. `build.py <proj>` … words.json + edl.json → `remotion/src/video.json`（字幕同期・文節改行・話者分離・判定vt）。各clipに **`seEvents`/`framing`** を arc.json から流し込む。
3. Remotionテンプレート（`remotion-template/`）を配置。`styles.ts` の PALETTE/SIZE/ZONE を arc の実測値に更新。
4. **各次元の実装（テンプレに内蔵済み）**:
   - テロップ: 色=体温（pink=女性profileラベル / 不採用=青グロー / キー句=枠・色はトーンから）。**機械的なOK/NG色分けはしない**。★**動的様式も参考の実測に従う**: 逐次行出現（プロフィール行が発話同期で1行ずつ+SE）/ 縮退（全画面大カード→隅の小カード化）/ 残留カード（説明中も文脈カードを画面隅に保持）/ 判定テロップの別階級（通常キャプションと別クラスの最大サイズ・グロー）。形態は参考ごとに違うので毎回 `telop-analysis-methodology.md` 15節の全要素照合で確定する。
   - フォント: 強調手段（**重要セリフは別書体**）。★**参考書体そのもの（または視覚的に区別不能な一致）を使う**。字形特徴から実際のフォント名を特定し、入手可能ならそのフォントを`public/fonts/`へ置き`fonts.ts`の`CUSTOM_FONTS`へ→telop/captionの`font`キーで適用。「系統が近い」程度のフリーフォントで妥協しない（詳細・特定手順は`references/telop-analysis-methodology.md`12節）。全体完コピは`fontFamily`差替。縁取り/グロー/per-char色/縦書き/可変ウェイトもCSSで実測値どおりに再現（独自デザインを足さない）
   - SE: `ClipSE` が arc の `seEvents` をビート単位で再生。**谷は無音（温存）/初回オチが最強**。素材アセット `public/se/`（ding=煽り明・impact_mid=衝撃中・impact=衝撃強）。★**raw clip の baked SE を必ず測ってから合成可否を決める**（判定無音バグの教訓・se-analyst.md）。★**SEの紐付け単位は「テロップイベント」**（プロフィール行の逐次出現・判定・大カット切替のそれぞれ）であって「クリップに1発」ではない。SE数/分を参考と±30%で一致させる（実証: 参考28発 vs 出力6発で差し戻し。参考は概ね全テロップ遷移にSEが同期していた）。
   - フレーミング: `PunchIn`。★**発火ゲート**＝`detect_shots.py` で `n_shots==1`（単一固定ショット）なら **framing オフ・等倍**（謎ズーム禁止）。寄り引きはショット境界のハードカット切替のみ。同一ショットのスムーズズーム禁止。★**ズーム切替は必ず「動機ベース」**＝判定語の頭・キー句・切り返し・リアクションの瞬間にだけ静的ズーム（`framing:{primitive:"寄り",zoom:1.08〜1.13,static:true}`）を切り替える。**「隣接クリップで機械的に交互」は禁止**（反面教師: カット検出数値を通すために1.0⇄1.08を2秒ごとに交互させた出力が「意味のないパンプ運動」になりユーザーに差し戻された。数値は合格・知覚は不合格＝Goodhartの法則）。同じ倍率が数クリップ続いてよい。カットの可視性は倍率でなく編集の動機から生まれる。
5. `npx remotion still` で数フレーム確認→`npx remotion render`（~60-90s）。

## Phase 5 — 4層検証（`references/verification.md`）★全層100点になるまで反復
**重ね合わせ：次元内∧次元間∧情緒整合∧多重サンプリング を全層通過で納品。WARN/FAILが1つでも残れば差し戻し→修正→再検証を回数無制限で繰り返す。**
- 層1 次元内: テロップ同期≤0.3s/消し忘れ/空間重なり（`check_overlap.py`）/カット位置/SE±0.15s/尺/フレーミング（謎ズーム無し）
  - **カット境界の逐語照合（必須）**: `final.mp4`をフル文字起こしし、`work/words.json`＋`edl.json`のin/out点と突き合わせ、語の途中・文の途中で意図せず切れていないか確認（`references/verification.md` 1.5節）
  - **意味整合ゲート（必須）**: 組んだ台本と完成版文字起こしを「会話として通読」し、指示語の宙浮き・Q&A不一致・文中エントリ・前提欠落ゼロを確認（`verification.md` 1.9節・逐語照合とは別検証）
  - **テンポ・密度ゲート（必須）**: `verify_tempo.py out/final.mp4 <参考動画>` で cuts/min・ショット長中央値・最長ショット・テロップ遷移/分・SE/分 を参考と照合。FAIL 1つで差し戻し（`references/verification.md` 1.6節）
  - **テロップ全要素パリティ（必須）**: 参考と出力の同ビートのフレームを1枚ずつ横並び目視し、デザイン/タイミング/サイズ/改行/意味単位の表示/入り方/縮退/残留の全要素一致を確認（`telop-analysis-methodology.md` 15節）。**静止画一致だけでは不十分——「入り方」は動き（フレーム列）で照合する**
- **精読プロトコル（必須・1.10節）**: アトム整合(切り詰め禁止)→クリップ単体ASRの期待テキストdiff→構造化通読(文字回答)→第三者敵対読み→`seidoku_report.md`保存。レポートなしに納品不可
- **★知覚ゲート（最終合格判定・editor-in-the-loop）**: 統計ゲートは**落第検出専用の必要条件**であり、合格判定には使えない（実証: ズーム交互ハックで全数値PASSの機械編集が差し戻された=Goodhart）。合格は次でのみ出す: (1)**全カット境界**を境界前後のフレーム列＋音声で1箇所ずつ検分（等間隔刻み感・動機なきズーム・変速のガクつき・呼吸の有無） (2)**全テロップ出現**を動きとして参考の実測と照合 (3)**通し視聴**（全編をフレーム連続＋音声で検分）して違和感を列挙→ゼロまで修正反復。`references/verification.md` 1.8節
- 層2 次元間: 山(締強)で**複数次元が収束**（3次元以上）/谷に強演出の誤爆なし
- 層3 情緒整合: 山谷の配置/判定の**トーン描き分け**/締めは弧に1つ/ギャップが立つ
- 層4 多重サンプリング: 色/SE/サイズは N≥3 確定・反例スキャン・混入ガード
- 最終ゲート: `verify_screenshots.py` で全テロップ目視（**フォント完全一致を含む**）＋ SE再検証（`analyze_se_motion.py`）＋ 山の収束レポート ＋ 逐語照合レポート。
- 1項目でも未通過なら100点ではない。修正→再検証を全項目PASSまで継続する。

## 心得
- **情緒を先に読む、次に必要な視覚/音/カットだけ測る**。機械測定（色/SE/shots）は語彙を埋めるためで主役でない。
- **emphasis は標高で決まる**。谷を作るから山が立つ。前フリ・列挙・つなぎは意図的に「抜く」。
- **色は体温・OK/NGの機械色分けは禁止**。判定は描き分ける。
- **framing は素材が持っていれば使う、無ければ作らない**（単一固定ショットは謎ズームの元）。
- **SE は raw clip を測ってから**。谷は無音・初回オチ最強の温存。
- カット選定とデプロイ判断はユーザー承認。検証は1観点・1層で終わらせない。
- **カット境界は必ず完成版とソースの文字起こしを突き合わせて事実確認する**（「たぶん文の切れ目」では判定しない）。
- **テンポは見た目と同格**。分析で測った cuts/min・SE/分・テロップ遷移/分は、EDL設計に変換して初めて意味を持つ。設計直後に自分の EDL のクリップ数/分を参考と数値比較する（分析→設計の変換ドロップが実際の敗因になった）。
- **フォント・色・装飾はオリジナルを足さず参考と完全一致させる**。近似は実測不可・入手不可の最終手段のみ。**prprojがあるならフォントはblob直抽出で確定させる（目視照合のみは禁止・誤特定の実証あり）**。
- **検証は1回で合格にしない**。全層・全項目が100点になるまで検証→修正を繰り返す。
- 参考動画が変われば資産（数値・語彙の値）は再分析。**手順とトーン語彙の枠だけ再利用**。
