# カット選定・検品・修正の厳格ルール（正本）

制定 2026-07-28。案件O（中古車販売） 17_車種H の制作で得た全学びから策定。
**このファイルは動画のカット編集を行うたびに全文を読み直す。読まずに着手してはならない。**

---

## 第0章 大原則

### 0-1. 三つの禁止

1. **単語一致でカットを選ばない** — 文脈と話者の物理的な動作で選ぶ
2. **1案しか出さない選定をしない** — 常に3〜5候補を挙げてスコアリングする
3. **py・prproj・PNGを上書きしない** — 必ず新しい版として作り、台帳に履歴を残す

### 0-2. 三つの必須

1. **B-rollを置く前に、隠すA-rollを必ず見る**
2. **検品は毎回「全フレーム目視・音声波形・ルール再読・過去ミス全チェック」の4点を行う**
3. **95点を超えるまで修正ループを回す**

### 0-3. 判定範囲の大原則

> 「AロールのところにBロールが被さっているなら、実際に見えているのはBロールなわけだから、
>   その部分の音声も使う（生かす）必要があるわけね。そこは元のままでいいんだよ」

- 冗長・無音の判定は **A-rollが素で見えている区間だけ** に限る
- B-rollが被っていれば画は成立しているので触らない
- 「B-rollを外してA-rollに戻す」は低密度のA-rollを露出させるだけで逆行

## 第1章 カット選定の手順（必ずこの順で行う）

### 手順1. 素材の全時間窓をフレーム単位でラベル化する

**全素材について、0.1秒刻みでスライドさせた全時間窓に「何が写っているか」のタグを付ける。**

- 素材DBの分類名を信用しない（IMG_6224が「車両外観-ディテール」と分類されていたため、
  実際は「アオリの外側と荷台の壁」が主役なのに荷台系の候補から外し続けた）
- 同じ素材でも時間窓で写るものが変わる。必ず全区間を見る

| 実例 | 前半 | 後半 |
| --- | --- | --- |
| IMG_6222 | 0.10-2.60 荷台の中 | 2.60-3.85 アオリの外側 |
| IMG_6223 | 0.10-1.60 荷台とキャビンが1枚 | 1.60-4.02 真横→ホイール |
| IMG_6219 | 0.30-3.60 前席（付箋なし） | 3.60-5.55 ステアリング（黄色い付箋＝NG） |

- **NG要素**（付箋・別車両の値札・第三者の顔）が写る区間は必ず記録し、選定から除外する

### 手順2. A-roll側の実態を確定する

B-rollで隠す区間の下で、話者が**どこに立ち・何に触れ・何を実演しているか**をフレームで確認する。

- **指示語（こちら・これ・ここ）の実体は、話者の手元と立ち位置でしか決まらない**
- **多義語**（外側・仕事・積む）は文脈で意味が変わる。辞書的な一致で選ばない
- **実演中（話者が対象物を動かしている）はB-roll禁止** — 実演はA-rollにしか存在しない

### 手順3. B-roll表示中の発話を「語単位」で抽出する

「重なるカットのtext全体」ではなく、**タイムライン区間→ソース区間（カットをまたぐ場合は複数）→語の抽出**で厳密に出す。

これを実装して初めて、あるスロットの実際の発話が「ですね。」だけだと判明した。

### 手順4. 3〜5候補を挙げてスコアリングする

**全素材×0.1秒刻みの全時間窓を総当たりし、100点満点で採点する。**

| 配点 | 項目 | 内容 |
| --- | --- | --- |
| 45 | 内容一致 | そのスロットで見せるべき対象が写っているか |
| 15 | 寄り引き | 機能・部位の名指しは寄り／空間・雰囲気は引き |
| 15 | 新鮮さ | 直近で同じ素材・同じ絵を使っていないか |
| 10 | 尺の充足 | 必要尺を満たすか |
| 5 | 画質 | デジタルズームの倍率が高いほど減点 |
| −100 | NG要素 | 付箋／別車両の値札／構造ガード違反は即失格 |

- **「B-rollを置かない」も選択肢として必ず採点対象に入れる**
  （実例: あるスロットは最高点57.0点しかなく、置かないのが最適だった）
- **上位3〜5案を必ず書き出し、なぜ1位を選ぶかを言語化する**

### 手順5. Codexに敵対的レビューを依頼する

選定案が固まったら、**必ずCodexに敵対的レビューを投げる**。

```
mcp__codex-cli__codex に以下を渡す:
  - 各スロットの発話（語単位）
  - 選定した素材と時間窓、その理由
  - 却下した候補とスコア
  - A-roll側で何が起きているか
プロンプト: 「この選定を否定してください。内容が合っていない箇所、
  より良い候補を見落としている箇所、文脈を読み違えている箇所を全て指摘してください」
model は gpt-5.5 を指定する
```

Codexの指摘は必ず1件ずつ検証し、採否と理由を台帳（`revision_record_db`）に残す。

### 手順6. 構造ガードを機械的に強制する

コードで判定し、違反したら `SystemExit` で止める。

- 伏線の対象（例: 荷台）は、その回収発話より前に置かない
- 主対象（例: 車の外観）は、登場発話より前に置かない
- 冒頭の問いかけ区間にはB-rollを置かない

## 第2章 A-rollの扱い

### 2-1. テンポを合わせる手段は3つ。①だけで解こうとしない

| | 手段 | 使う場面 |
| --- | --- | --- |
| ① | B-rollを被せる | 画に見せる価値があるとき |
| ② | A-rollのまま見せる | 話者の表情・実演の方が分かりやすいとき |
| ③ | **尺ごと削る** | 無音・冗長で、隠す価値も見せる価値も無いとき |

### 2-2. 参考の構造は「塊（クラスタ）」

- 参考16はB-roll 9本を**5つの塊**にまとめ、塊は4〜8秒、塊と塊の間に8〜15秒の長いA-rollを残す
- **「6秒超のA-rollは間延び」は誤り**。均等に散らすのが間違い
- クラスタ内は必ず隙間ゼロで連結する

### 2-3. ★言葉は絶対に言い切らせる

- カット点は**波形の無音が0.18秒以上続く区間の中にしか作らない**（語中の谷は実測104ms）
- その無音の中で、直前の語の end より後ろでしか out を打たない
- out は語末+0.05秒、in は次の語頭より0.05秒手前
- 打った点の前後で実波形が本当に無音であることを再確認する
- **whisperの語タイムスタンプは絶対視しない**（「こちら」1.94秒、「値」1.10秒とスミアする）
- **最終確認はレンダー後の音声を再文字起こしして台本と突き合わせる**

### 2-3b. ★「語の内側で切らない」だけでは足りない。文節の切れ目まで見る

「語の内側で切っていない」ことを確認しても、**語の境界が文節や句の途中**なら、
繋いだ結果が不自然な会話になる。語レベルと文節レベルは別の検査。

- 語レベル: 切り位置が語の start-end の内側に落ちていないか（`qc_cut_words.py` 相当）
- **文節レベル: 継ぎ目で発話を捨てている場合、次カットの先頭が文節頭になっているか**

**判定の分け方（これを間違えると誤検出する）**

| 種別 | 判定 |
| --- | --- |
| **地続き**（継ぎ目で発話を1語も捨てていない） | 元の発話がそのまま続くので**常にOK**。句の途中で終わっていても次カットが受ける |
| **発話を捨てて接合** | 次カットの先頭が助詞・助動詞・接尾辞・補助記号で始まっていたら**FAIL**（前の句の続きになっている） |
| **素材の順序が前後** | 台本順に組むため元の時間軸を跨ぐ場合。捨てた発話の概念が無いので対象外 |

★**「地続き」の定義は「発話を捨てていないこと」であって、無音の長さではない。**
無音0.05秒未満などで判定すると、語を1語も捨てていないのに0.1〜0.4秒の無音を挟むだけの
継ぎ目を「捨てている」側に数えてしまう（2026-07-31 18_PJO_R4 で実際に踏んだ）。

**なぜこれが要るか**: 切り位置を谷（-42dB以下が0.08秒以上）にしか置かない規則を守っていると、
人は文節や句の切れ目で息を継ぐので**副作用として自然と文節頭に落ちる**。
だが規則が壊れたとき（谷の閾値を緩めた・トリム工程が後から切り位置を動かした等）に
気づけないので、必ず**独立した検査として全継ぎ目を機械で検算する**。
実例(2026-07-31 18_PJO_R4 v10): 26継ぎ目 = 地続き14 / 発話を捨てて接合11 / 順序前後1 → FAIL 0件。

**実装**: `reference-video-clone/scripts/check_join_phrase.py`（案件へコピーして使う）。
入力は `work/group_words.json`（息継ぎ単位ごとの単独文字起こしの語列）と `work/cutlist.json`。

**切り位置を動かす工程が複数あるなら、全部に語境界吸着を入れる**。
実例: カットリスト生成に入れただけでは、後段の無発話トリムが切り位置を動かして壊していた
（「結構」が「っ構」に、「ちょっと」が「っと」に聞こえる欠陥が再発）。

### 2-4. カメラワークの判定

位相相関で連続フレーム間の平行移動量(dx, dy)を測る。フレーム差分だけでは「動きが大きい」しか分からない。

- 横移動の総量 / 正味の移動 / 往復度 / ピーク を出す
- **移動量が大きいこと自体は悪ではない。移動の先に見せるものがあるかで決まる**
- 被写体が写らない振り回しは、音声を残したままB-rollを載せて潰す

## 第3章 検品ルール（毎回必ず行う4点）

### 3-1. 毎回の必須4点

**この4点は例外なく毎回行う。1つでも飛ばしたら検品したと言ってはならない。**

1. **全フレーム目視**
   - 設計値から全ショットを列挙し、1秒未満は全数を目視する
   - B-rollは使用区間のフレームを実際に見る（素材名や分類で判断しない）
   - B-rollが隠しているA-rollも見る
2. **音声波形**
   - 全カット境界の波形不連続（プチノイズ）を測る。段差0.06超は0件であること
   - A-roll素見え区間の無音を0.25秒閾値で全数出す
   - 完成音声を再文字起こしし、語尾切れがないことを確認する
3. **ルール再読**
   - このファイル（CUT-QC-RULES.md）を全文読み直す
4. **過去ミスの全チェック**
   - 第5章のチェックリストを1件ずつ潰す

### 3-2. 3回に1回は全面チェック

修正ループの3周に1回は、上記に加えて次を行う。

- 全素材の全時間窓ラベルを作り直す（新しいNG要素が無いか）
- 全スロットのスコアを再計算し、現行を上回る候補が無いことを確認する
- Codexに全フレーム画像を渡して目視レビューを依頼する
- 参考動画との数値比較（カット/分・尺中央値・占有率・素見え箇所数）をやり直す

### 3-3. Codexへの全フレーム目視依頼

```
1. レンダー出力から全ショットの代表フレームを書き出す（1ショット3枚: 頭・中・尻）
2. スロットごとに「発話 / 画のラベル / 画像パス」をまとめる
3. mcp__codex-cli__codex に渡し、
   「各ショットについて、発話と画が合っているか、
     不要なカット・一瞬の紛れ込み・不自然な繋がりが無いかを指摘してください」
   と依頼する（model: gpt-5.5）
4. 指摘を1件ずつ検証し、採否を台帳（`revision_record_db`）に記録する
```

### 3-4. 機械検査の必須項目（全て0件であること）

> ★数値の単一正本は `short-video-qc/references/gates.template.json` の `universal_thresholds`
> ＋案件project.jsonのthresholds実測上書き（2026-07-30 D3決定）。下表の数値は既定値の例示。

| 項目 | 基準 |
| --- | --- |
| 0.40秒未満のショット | 0件 |
| B-roll間の20フレーム未満の隙間 | 0件 |
| 孤立フレーム（1枚だけ別の絵） | 0件 |
| 黒フレーム | 0枚 |
| 0.5秒以上の静止 | 0箇所 |
| A-roll素見え区間の無音（0.25秒以上） | 0箇所 |
| 波形不連続（段差0.06超） | 0件 |
| テロップ同期のズレ | 0件 |
| 映像をはみ出すテロップ・SE | 0件 |
| SEの発音（各位置のRMS） | 全て−60dB以上 |
| A-roll末尾とテロップ末尾の差 | 0フレーム |
| **切り位置が語の内側に落ちている** | **0件**（2-3b） |
| **継ぎ目の接合点が文節頭でない**（発話を捨てている継ぎ目のみ） | **0件**（2-3b） |
| **テロップが単語の途中で改行・分割されている** | **0件**（折り返しは文節頭→語境界の順で探し、文字数二分は使わない） |

### 3-5. 検出器の作り方（取りこぼさないために）

- **設計値（カット表・B-roll表）から全数列挙する**。画像解析は補助に回す
- 画像解析を使うときは**テロップ帯（画面の縦45〜72%）を除外**し、輝度ヒストグラム距離も併用する
  （テロップの切り替わりと、歩き＋パンの速い動きを誤検出するため）
- 閾値は必ず記録し、「なぜその値か」を書く

## 第4章 修正ループ（95点を超えるまで回す）

### 4-1. 採点基準（100点満点）

| 配点 | 項目 | 減点の仕方 |
| --- | --- | --- |
| 30 | 内容一致 | 発話と画が合っていないスロット1件につき −10 |
| 20 | 機械検査 | 第3章3-4の項目が0件でないもの1件につき −5 |
| 15 | テンポ | 参考のカット/分・尺中央値・占有率から±30%外れたら −5ずつ |
| 15 | 構造 | 伏線の破綻・登場順の違反1件につき −15 |
| 10 | テロップ | 同期ズレ・改行破綻・はみ出し1件につき −5 |
| 10 | SE | 未発音・位置ズレ1件につき −5 |

**95点未満なら必ず修正してもう一周する。** 95点は「機械検査が全て0件」かつ「内容不一致が0件」でなければ届かない。
（2026-07-30定義分離: この無制限ループは**機械検査0件までの修正ループ**を指す。Codex採点ループの上限は5R＝SCORING-LOOP.md。5Rで収束しなければ残指摘をユーザー判断事項として提出する）

### 4-2. ループの手順

```
1. 検品（第3章の4点必須。3周に1回は全面チェック）
2. 採点
3. 95点未満なら修正 → 新しい版として保存 → 台帳に記録 → 1へ戻る
4. 95点以上なら、最後にもう一度だけ全面チェックを行って確定
```

### 4-3. 修正は「反復」しないと終わらない

短ショットの修復は1回では終わらない。処理が互いに新しい問題を生む。

**確立した手順**:

1. 短ショットに対し 手1=直後のB-rollを前へ伸長 → 手2=直前のB-rollを後ろへ伸長 → 手3=尺ごと削る
2. カットを削除区間で割ったあと、閾値未満の断片が出たらその断片も削除区間に加える
3. **断片が0件になるまで反復する**

## 第5章 過去ミスのチェックリスト（毎回1件ずつ潰す）

### 選定

- [ ] 単語に飛びついていないか（「倒して」→後席、「外側」→車体外観、「外仕事」→運転席 の誤り）
- [ ] 素材の分類名で候補を絞っていないか
- [ ] 素材の使用区間を決め打ちしていないか（他の時間窓を検討したか）
- [ ] 3〜5候補を挙げたか。「置かない」を候補に入れたか
- [ ] Codexの敵対レビューを受けたか
- [ ] B-rollが隠しているA-rollを見たか
- [ ] 実演区間にB-rollを被せていないか
- [ ] 目的（値札を隠す等）だけでB-rollを入れ、中身を選ばなかったことはないか

### 検品

- [ ] 「全フレーム検品した」と言えるだけのことをしたか。していないなら正直に言ったか
- [ ] 数値だけで判断せず、目視で裏を取ったか
- [ ] 検出の閾値は十分に厳しいか（短ショット0.40秒／無音0.25秒）
- [ ] 設計値から全数列挙したか（画像解析だけに頼っていないか）
- [ ] テロップ帯を除外して画像解析したか
- [ ] **切り位置が語の内側に落ちていないか**を全カットで検算したか
- [ ] **継ぎ目の接合点が文節頭か**を全継ぎ目で検算したか（2-3b。語レベルだけでは足りない）
- [ ] 切り位置を動かす工程が複数あるとき、**全部に語境界吸着を入れたか**（片方だけでは後段が壊す）
- [ ] **テロップが単語の途中で改行・分割されていないか**（文字数二分を使っていないか）

### 副作用

- [ ] B-rollを置いた後、A2をクリアしてSEを置き直したか（B-rollの音声がA2に流れ込む）
- [ ] テロップPNGを上書きする前に世代退避したか
- [ ] prprojを戻すときPNGも戻したか
- [ ] SEの音量を再適用したか（実値を get_effect_properties で確認したか）

### 履歴

## 第6章 履歴管理（絶対に漏らさない）

### 6-1. py・成果物

- **絶対に上書きしない**。必ず `_v2` `_v3` のように新しい版として作る
- 却下された版も消さない
- prproj は `work/prproj_versions/` へ、テロップPNGは `work/telop_png_versions/<v>_<日時>/` へ退避
- ロールバック用スナップショットは prproj・全JSON・PNG・レンダー済みMP4 を同梱し、
  README に「PNGも戻すこと」を明記する

### 6-2. 台帳の `revision_record_db`（修正記録DB）に毎回書く

★置き場所は VOPS Ledger（2026-08-12 に Notion から移管）。MCP `ledger_upsert` で書く。

**カット選定を変えたら、pyを作ったら、必ずその場で書く。まとめて後で書かない。**

必須項目:

- 記録名 / バージョン / 対象ファイル_pyパス（フルパス）
- 変更内容 / 変更理由（ユーザー指摘は原文を引用する）
- 採用状態（採用・却下・旧採用・未判定）/ 却下理由
- 検証方法（実測値を数字で書く）

## 第7章 参考の文法（実測値）

### 7-1. 寄り引きは発話の種類で決まる

- **具体的な装備・スペックを名指し → その物体が画面いっぱいの寄り**
- **雰囲気・全体の印象 → 引き（全景）**

### 7-2. B-rollにズーム加工は足さない

参考のB-rollにはスケール・位置のキーフレームが一切ない。動きは「テロップのアニメ」と
「素材自身のカメラパン」で作る。ただし素材に寄りが無く、「対象を見せる」という上位基準が
守れない場合に限り、1.8〜2.25倍のクロップで寄りを作ってよい（2.5倍超は画質が破綻）。

### 7-3. SEの文法

- 18.9発/分。94%が「テロップの開始と同時」に鳴る
- 音量は約半数に指定あり（中央値−20dB）
- Premiereのレベル変換式: `normalized = 10^((dB−6)/20)`

### 7-4. テロップ

- 位置は固定（画面の約53%）
- 改行は実フォント幅で判定し、収まるなら必ず1行。上限は画面幅×0.74
- 表示時刻は秒の手打ち禁止。文字列検索でカット表に自動追従させる

# 第8章 18・19の制作で見つかった穴（2026-07-29 追記・違反厳禁）

17で「一瞬映る／無音」を潰したあと、18と19を通しで作って**さらに5つの穴**が出た。
どれも「今までの検査を全部通っていたのに、完成MP4には欠陥が残っていた」という形で出ている。
**個々の工程が基準を満たしていても、繋いだ結果は別**というのが共通の教訓。

## 8-1 「無音」と「発話が無い」は別物

波形が SIL_DB を下回るかどうかだけで無音を判定していると、
**風・足音・車の音で -33.8dB もある「誰も喋っていない5秒間」**が素通りする。
18で完成尺に「テロップが1枚も出ない4.6秒」として現れた。

→ 検出は**3本立て**にする。
  1. カット点が無音の中にあるか（`build_cuts`）
  2. カットの**内側**に無音がないか（`trim_inner_silence`）
  3. **発話が無い区間**がないか＝語と語の間が0.60秒以上空いていないか（`trim_nospeech`）

## 8-2 繋いだ結果に生まれる無音

各カットは前後に KEEP_SIL(0.12秒)ずつ間を残している。
繋ぎ目では **0.12 + 0.12 = 0.24秒** が連続し、検品基準(0.25秒)を超えることがある。
19で6箇所出た。

→ **カット表どおりに繋いだ音声を実測して**残っている無音を詰める（`trim_join_silence`）。
→ ★**詰める側のしきい値は、検品する側の基準と必ず一致させる**。
   19では詰める側が0.35秒・検品側が0.25秒で食い違い、その間の無音が全部素通りしていた。

## 8-3 テロップは「完成音声の再文字起こし」からしか作らない

元音声の語タイムスタンプ＋カット表で組むと、カット境界で文言が壊れる。
18で「ーレスになって」「両本体価格」「ホ」という壊れたテロップが出た。

→ カット表どおりに音声を繋いで**もう一度文字起こしし、その語列だけ**からテロップを作る（`final_audio` → `build_telops_final`）。
→ 区切りは **fugashi の形態素で文節頭にしか作らない**。次の位置では絶対に切らない:
   ・語の途中（最終モーラ切れ。「お願いいたしま/す」は差し戻し事例）
   ・カタカナ複合語の内側（「ドライブ/レコーダー」）
   ・助詞・助動詞・接尾辞の前（「ありがとうござい/ます」）
   ・副詞・連体詞・接頭辞の直後（「そう/いった」「ぜひよろしくお/願い」）

## 8-4 ★whisper は固有名詞を作る（納品不可の欠陥）

「完成音声を再文字起こしすれば実際に聞こえる音と一致する」という前提は崩れる。
19で実際に起きたこと:
  ・「クリエイターさん」→「くねよしさん」（人名でない語を人名にした）
  ・「本当にもう荷物も」→「荷物も使えるんですよ荷物も」（存在しない文が生えた）
  ・人名「国吉」→「くねよし」（**固有名詞の誤字は納品不可**）
  ・同じ台詞を1回多く重複させた

→ 完成MP4の音声を**もう一度**文字起こしして、テロップ文言と突き合わせる（`qc_speech_generic`）。
→ 食い違った箇所は**推測で直さない**。その区間だけを切り出して単独で文字起こしし直し、
   元音声の文字起こしとも突き合わせて確定させてから訂正表に書く（`apply_corrections`）。
→ 訂正後の文言は**1文字ずつの語に分けて時刻を按分**する。
   1語にまとめると全文字が同じ時刻を持ち、テロップ表示が0.6秒早まる（19で実際に起きた）。

## 8-5 同一素材・同一区間の使い回しは機械で止める

18で3件出た。IMG_6233の荷室を39.4秒と96.8秒、IMG_6236の前席を66.6秒と82.4秒（16秒差）、
IMG_6230の正面を0.8秒と41.5秒。**全ショットを目視するまで気づかなかった**。

→ B-roll生成スクリプトの末尾で「同一素材・同一開始点」の重複を数え、
   **0件でなければ SystemExit で止める**。目視に頼らない。

## 8-6 配置後は必ずクリップ数を検算する

B-rollをV2に置くとリンク音声がA2へ流れ、**既にあるSEを上書きして消す**。
18で4発、19で断片1件が発生した。CUT-QC-RULESに書いてあったのに再発した。

→ 置いたあとに **V1/V2/V3/V4/A2 のクリップ数を設計値と突き合わせる**。
→ SEの音量は**順番でなく開始時刻で照合して**当てる。断片が1つ混ざるだけで以降が全部ずれる。
→ A2の末尾が総尺を超えていないか確認する（超えると末尾に黒フレームが出る。18で31枚）。

## 8-7 しきい値を使う前に、その配列の単位と値域を表示して確かめる

`env.npy` は**線形振幅(0〜1)**なのに `env > -42.0`(dB) と比べて、
27件すべてを「語を削っている」と誤検出した。条件が常に真になっていた。
→ しきい値判定を書いたら、必ず `min/max/中央値` を出して単位が合っているか目で見る。

## 8-8 数値のために上位規則を破らない

18はショット尺の中央値だけ参考から+40%外れた（2.10秒 vs 1.50秒）。
しきい値を下げて組み直しても2.07秒にしかならず、1.50秒まで詰めるには**語の途中で切るしかない**。
参考16は発話の切れ目が多い素材、18は一続きの発話が長い——**素材の性質の差**。

→ 統計ゲートは**落第検出専用**であり、合格判定には使えない（Goodhartの法則）。
   数値を合わせるために「言葉を言い切る」等の恒久禁止事項を破ってはならない。
   外れを残す場合は、**なぜ外れたのか・何を試したのか・なぜ詰めないのか**を台帳に書く。
