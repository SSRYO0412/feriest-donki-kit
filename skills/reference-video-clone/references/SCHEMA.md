# 多次元 情緒の弧シート — スキーマと演出プリミティブ語彙

参考動画の分析と、新素材の編集設計の **両方** がこの同じ構造を使う（分析＝読む／設計＝書く）。
背骨は「情緒の弧」1本。テロップ・カット・SE・間・フレーミングは、その背骨にぶら下がる **トラック**。

## arc.json（中核データ構造）

```jsonc
{
  "video": "Download.mp4",
  "mode": "reference" | "source",     // 参考分析か素材設計か
  "fps": 30, "width": 576, "height": 1024, "duration": 77.7,
  "beats": [
    {
      "id": "b01",
      "arc": "candidate_1",            // 物語の弧（候補/トピック単位）
      "tone": "バッサリ",              // この弧の情緒タイプ（tone-library のキー）
      "t_start": 0.0, "t_end": 9.6,
      "gap": "経験0年+夜職",           // 好奇心を駆動する矛盾/意外性（無ければ null）
      "landing": "不採用！",           // この弧の「締めの一文」＝1つだけ
      "rows": [
        {
          "t": 0.0, "text": "28歳、美容師歴0年、夜職経験ありの女性",
          // ── 背骨（次元非依存・editorial-analyst が付ける）──
          "emotion": "二重の引っかかりの提示",
          "altitude": "谷" | "上り" | "山",
          "decision": "締強" | "締柔" | "立" | "抜",
          "why": "視聴者に先に判定させる撒き餌",
          // ── 各次元トラック（specialist が付ける・無ければ null）──
          "telop":   { "primitive": "立:属性", "color": "pink", "note": "女性ラベル" },
          "cut":     { "primitive": "提示カット", "note": "候補の引き画" },
          "se":      null,
          "pace":    { "primitive": "標準" },
          "framing": { "primitive": "引き", "note": "全員が見える俯瞰" }
        }
      ]
    }
  ]
}
```

- **row = 文（文章単位）** が原子。単語単位では切らない。
- 背骨3項目（emotion/altitude/decision/why）は editorial-analyst だけが書く。確定後は各 specialist が同じ row に自分の次元の列を足す。
- `decision` は **演出プリミティブの上位カテゴリ**。各次元はこの decision に整合する primitive を選ぶ（山に抜きを当てない）。

## 演出プリミティブ語彙（次元 × 意図）

各次元は「情緒(decision/tone)→その次元での具体演出」を、下の決まった語彙で書く。
自由記述しない＝レンダラ（cut.py / SE合成 / Remotion）が1:1で解釈できるように。

### テロップ（telop）
| primitive | 意味 | 実装 |
|---|---|---|
| `締強` | オチの大判定 | verdict role＋最大サイズ＋pop。**判定は通常キャプションと別階級**（全画面級サイズ/グロー等・参考の実測に従う） |
| `締柔` | 殴らない締め（優しい否定等） | 大判定語なし・中サイズ・枠なしで文提示 |
| `立:キー句` | 決め台詞のキー句を隔離 | caption.hl＋色（色はtoneから） |
| `立:属性` | 候補の属性ラベルを強調 | profile強調ラベル＋色 |
| `抜` | 谷の地の文 | 通常字幕・最小サイズ |
| `温度:<色>` | 色は単語でなく体温 | yellow/red/green/pink/blue/orange |
| `逐次行` | 属性/列挙を発話同期で1行ずつ出す | profile等の行を発話タイミングで追加表示（各行にSE随伴が既定・参考の実測に従う） |
| `縮退` | 大提示→文脈保持へ格下げ | 全画面級カードを判定/説明の開始で画面隅の小カードに縮小 |
| `残留カード` | 説明中も文脈を画面に残す | 説明/理由の間、プロフィール等の小カードを隅に保持（途中から見た視聴者への文脈維持） |

★テロップの**形態（カード型/字幕ロール型/ボックス型/逐次行型…）は参考ごとに別物**。この表は語彙であって既定様式ではない。毎回 `telop-analysis-methodology.md` 15節の全要素照合で参考の実測に合わせる。

### カット（cut）
| primitive | 意味 | 実装 |
|---|---|---|
| `提示カット` | 人物/対象を見せる引き | クリップ頭で対象が画に入る |
| `切り返し` | 質問→反応へ視点転換 | 話者/リアクションへカット |
| `溜めカット` | 山の直前で間を作る | 判定直前に一拍置く |
| `余韻ホールド` | 山の直後リアクションを残す | 判定後の表情を切らずに保持 |
| `圧縮ジャンプ` | 谷を詰める | 無音/冗長をジャンプカット。**EDLでは複数クリップへの分割として実装**（クリップ内部に間を残さない） |
| `速度ランプ` | テンポ操作 | edl clip の `"speed"`（ピッチ保持倍速。説明/列挙=1.3〜1.5・判定/オチ=1.0厳守） |

★カット密度は語彙でなく**数値でも参考に合わせる**: 設計後の「クリップ数/分」「最長スパン」を参考の実測（detect_shots 複数閾値スイープ）と±30%以内で照合する。カット点は語境界±0.15秒。ただし**数値合わせは必要条件にすぎない**——切る位置・寄る瞬間は判断文法（正解編集の判断ログ）に従い、意味の節目で呼吸させる。密度を通すための機械的な等間隔刻み・ズーム交互は禁止（Goodhartの反面教師）。

### SE（se）
| primitive | 意味 | 実装 |
|---|---|---|
| `衝撃:強` | オチを最大音圧で打つ | 最強インパクトSE（弧の初回オチに温存） |
| `衝撃:中` | 節目の合図 | 中インパクトSE |
| `煽り:明` | 期待を上げる | 明るいding/whoosh |
| `無音` | 谷・余韻 | SE置かない（温存） |

★SEの紐付け単位は**テロップイベント**（逐次行の各出現・判定・大カット切替）であって「クリップに1発」ではない。**SE数/分を参考の実測と±30%で一致**させる（verify_tempo.py）。温存ロジック（谷は無音・初撃最強）は密度の中での強弱として両立させる。

### 間・尺（pace）
| primitive | 意味 | 実装 |
|---|---|---|
| `溜め` | 山の前で伸ばす | 判定直前の無音を残す・**必ず等速（speed 1.0）** |
| `詰め` | 谷を縮める | 冗長/無音をカット **かつ/または** `"speed": 1.3〜1.5`（ピッチ保持変速） |
| `標準` | 等速 | 触らない |

★変速の合格実例（実測）: 説明モノローグ=1.5倍速・判定パンチライン=1.07倍（ほぼ等速）。「説明は流す・オチは聴かせる」を速度差で作る。発話密度（語/秒）が参考より低ければ詰め/変速で合わせる。**変速は区間単位で平滑に**（同一モノローグの隣接クリップは同speed。クリップごとに細かく変えると声がガクつく=反面教師）。

### フレーミング（framing）
★**発火ゲート**：framing は素材の coverage がある時だけ発火。`n_shots==1`（単一固定ショット）は capture-limited
＝全 row `引き`（等倍）、寄り/パンチイン禁止（同一ショットへのスムーズズーム＝謎ズーム）。寄り引きは
**ショット境界のハードカット切替**で作る。詳細は `agents/framing-analyst.md` の発火ゲート。
| primitive | 意味 | 実装 |
|---|---|---|
| `引き` | 全体・状況（capture-limited 素材の既定） | 俯瞰/ワイド・等倍 |
| `寄り` | 感情に近づく（coverage 有時のみ） | 別ショットへハードカット（スムーズズーム不可） |
| `主役固定` | 対象を画面中心に（coverage 有時のみ） | 候補/判定者をセンターの別ショットへ |
| `反応抜き` | リアクションを拾う | 周囲の表情が入ったショットへ |

## 整合の原則（synthesizer と検証が使う）
- **山(altitude=山 / decision=締強)** のビートは **複数次元が収束**して立つべき（例：判定オチ＝締強テロップ＋衝撃強SE＋余韻ホールド＋寄り）。1次元しか立っていない山は弱い。
- **谷(抜)** に衝撃SEや寄りが乗っていたら誤爆。
- 各 `tone` には推奨プリミティブ束が tone-library にある。specialist はまずそれを引く。
