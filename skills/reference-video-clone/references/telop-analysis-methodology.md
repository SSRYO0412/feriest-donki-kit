# 参考動画 テロップ完コピ分析メソッド (再利用資産)

> このファイルは **手順(方法論)** の資産。**参考動画が変わったら、この手順を新しい参考動画に対して最初から実行し直す**。抽出した数値(色・位置・サイズ・タイミング)は参考動画ごとに別物なので流用しない。数値は `telop-spec.json` 側に動画ごとに保存する。

## 目的
参考動画のテロップ体系(色・外枠・位置・サイズ・タイミング・意図)を **0.3秒以内の精度** で実測し、別素材に寸分違わず適用できる構造化スペックに落とす。

## 手順

### 1. フレーム抽出 (0.2s 粒度)
```
ffmpeg -i <ref> -vf "fps=5" frames/f%04d.png   # t = (index-1)*0.2s
```
30fps素材でも5fps抽出で十分(テロップは0.2s単位で十分追える)。タイミングを詰める箇所だけ後で15fps再抽出。

### 2. テロップ遷移の自動検出 (zone-diff)
上部ゾーン(y 4–42%)と下部ゾーン(y 60–93%)で連続フレーム間のグレースケール差分を取り、平均+1.6σ超のピーク=テロップ出現/切替時刻。`scripts/transcribe.py` と同じ venv の numpy/Pillow を使用。
- 上部ゾーン = プロフィール/質問テロップ
- 下部/中央ゾーン = キャプション/判定

### 3. 時系列マップ (contact sheet)
`scripts/make_sheets.py <step> <cols> <rows>` で時刻ラベル付きタイルを生成し、テロップ種別の出現順序を把握する。

### 4. 色の実測 (★人物の帽子・木目背景に注意)
**最大の罠**: 被写体の帽子(オレンジ/赤)や木目壁が彩度の高いピクセルとして混入し、ボックス色を誤検出する。対策:
- ボックスは画面**中央(x 0.3–0.7)** に来るので中央ストリップで sample
- チャンネル条件で帽子と分離: 黄ボックス `G>160`、赤ボックス `G<60`(オレンジ帽子は `G>80`)
- それでも怪しい時は tight crop を 3x 拡大して目視確定
色名と用途をセットで記録する。

### 5. 位置・サイズの実測
白テキスト行(`(RGB>225).all`)の行密度から band を検出し、各テロップの y範囲(%)と文字高(% of H)を出す。サイズは必ず**フレーム高さに対する%**で記録(解像度非依存)。

### 6. タイミング × 発話 の対応
参考動画を word-level 文字起こし(faster-whisper)し、各テロップの出現/消滅が「どの発話の何秒後か」を測る。判定テロップは発話から **0.3秒以内**で出ているか確認。

### 7. 意図の言語化
各テロップ種別について「なぜその色か/なぜそのタイミングか/何を狙ったテロップか」を必ず書く。色は**使い分けの規則**(例: 黄=フック専用で乱用しない)まで言語化する。

## 高精度分析（ここから・必ず実施。スクショ/フレーム/音レベルまで掘る）

### 8. 出現エフェクト（フレームレベル）
テロップがどう出現するかを **30fps** で実測する。`analyze_se_motion.py anim <ref> <t0> <t1> <y0frac> <y1frac>`。
- テロップ帯のピクセル量を1フレームずつ追い、0→満タンの**立上り形**を見る:
  - **1フレームで急上昇 = ハードカット**（瞬時出現。多くの日本語高速編集はこれ＋SEで「パッ」と出す）
  - 数フレームかけて上昇・bbox一定 = **フェードイン**
  - bboxが拡大 = **スケールpop** / bboxが移動 = **スライド**
- 必ず**該当区間の30fpsフレームをストリップ化して目視**（計測だけだと前テロップの残像と混同する）。立上りフレーム前後6枚を並べて確認
- 記録: `entrance`（cut / fade / pop / slide）と所要フレーム数
- **★出現の「単位」も実測する**（1フレームの立上り形だけで終わらない）:
  - **逐次行**: プロフィール/列挙の行が発話に同期して1行ずつ増えるか、一括表示か（実測例: 大カードの属性行が発話ごとに追加され、各行の出現にSEが随伴）
  - **縮退**: 全画面級の大カードが、判定/説明の開始で画面隅の小カードに縮小して残るか
  - **残留**: 説明/理由の間、文脈カード（プロフィール等）が画面隅に保持され続けるか
  - **更新頻度**: キャプションが何秒ごとに切り替わるか（文節単位で毎秒級か、一文を数秒置くか）。テロップ遷移数/分は `verify_tempo.py` の実測と一致させる

### 9. SE（効果音）分析（音レベル・★BGM誤検出を避ける）
`analyze_se_motion.py se <ref> <telop_times_csv>`（telop_times は step2 の出現時刻）。BGM安全設計:
1. **HPSSで harmonic継続割合**を測りBGM有無を判定。継続割合が高い(>0.4)＝BGMが鳴り続けている → 持続的な harmonic 成分は **SE扱いしない**
2. SE = onset強度の**外れ値トランジェント(z>4)** かつ **テロップ出現と±0.15s同期**するもの。この「映像同期」が**話し声の破裂音・BGMの規則ビートを自動除外**する鍵
3. spectral centroidで種別推定: **>3kHz=明るいSE(whoosh/ding/pop)**、1.5-3kHz=中域インパクト、<1.5kHz=低域thud。話し声は~2kHzでテロップに同期しない
- 記録: 「テロップ出現の何割にSEがあるか」「SEの明るさ(centroid帯)」「判定/フックなど種別ごとにSEが違うか」
- 注意: BGMがある参考動画では step1 の判定を必ず先に出し、BGMのビートをSEと誤記しない

### 10. 改行ルール（★実測してルール化。CSS自動wrap厳禁＝語中で切れる）
複数行テロップ/字幕の改行を frames から実測し、**1行あたり文字数**と**改行位置の論理**を確定する。
- **改行は必ず文節（句）境界**。助詞(は/が/を/に/で/の/から/なら 等)や節の切れ目で折る。**語中で折らない／幅基準の自動wrapにしない**
  - 参考実測例: 「あんまり詳しくないですので」/「分からないですけど」(節境界)、「女性陣は」/「採用？不採用？」(は で折る)
- **1行の最大文字数**を実測。参考(576px幅)は **1行≈13字で幅の~90%** → 1080pxなら **≈10-11字/行**。フォントサイズから `usable_width / char_width` で算出し記録
- **プロフィール = 1属性1行**（実測: 「30歳女性」/「美容師歴5年」/「こども2人」）
- **キャプションは1-2行が基本**。長い発話は文節で2-3行 or 時間で逐次分割
- **実装(完コピ適用時)**: CSSの自動wrapに任せず、`fugashi`+`unidic-lite` で**文節単位に分かち書き**→max字数で貪欲に行詰め→明示的な行配列で描画(`white-space:nowrap`)。語中で絶対に切らせない。`pip install fugashi unidic-lite`
- 記録: telop_types[*] に `line_break_rule`(文節/属性単位) と `max_chars_per_line`

### 11. 逐語 vs 単語（どの文をそのまま出し、どの文を要約/キーワード化するか）
テロップ文言を **word-level文字起こしの実発話と1文ずつ突き合わせ**て分類（推測でなく照合）:
- **キャプション（流れる字幕）= 逐語**（喋った文をほぼそのまま。実測: 発話「あんまり詳しくないですので…」がそのまま字幕）
- **プロフィール / 質問 / フック = キーワード/要約**（発話から要点抽出・再構成。実測: 発話「30歳女性美容師歴5年お子さん2人いる」→テロップ「30歳女性/美容師歴5年/こども2人」(お子さん2人いる→こども2人)、発話「女性人だけで言ったら採用か不採用はどっちですか」→「女性陣は/採用？不採用？」）
- **判定 = 逐語ショート**（実際に言った答えの語そのもの「不採用！」）
- 照合手順: テロップ文字列が発話スパンと一致すれば verbatim、圧縮/語順変更/言い換えがあれば keyword とラベル
- **完コピ適用への含意**: 字幕は文字起こしからそのまま生成(逐語)、プロフィール/フック/判定はEDLで人が要約authoring(キーワード)。この役割分担を build に反映
- 記録: telop_types[*] に `verbatim_or_keyword`

### 12. フォント（★完全一致が原則。近似は最終手段）
- **★prproj（または編集プロジェクトファイル）が入手できる場合は、目視照合より先に必ずプロジェクトから直接抜く**。Premiereのprprojはgzip XMLで、`<Name>ソーステキスト</Name>` 直後の `Encoding="base64"` blobをデコードするとフォントのPostScript名が平文で入っている（ASCII走査で `Gothic|Mincho|Noto|Source|Hiragino|Yu|Koz` 等を抽出）。プロジェクトが複数動画を含む場合はblob内の日本語本文と対象動画のテロップ本文を突合して絞る。実装: `reference-video-clone/scripts/extract_prproj_fonts.py`。**実証(07具志さん2・2026-07-30): 目視照合の最有力候補（源真ゴシック/凸版文久見出し明朝）が両方誤りで、blob抽出の正解はNotoSansCJKjp-Black/SourceHanSerif-Heavyだった。同系統派生フォント（Source Han系とその派生）は目視では区別できない。目視のみでのフォント確定は禁止、目視は裏取りに使う**。
- prprojが無い場合のみ、以下の目視特定にフォールバックする（結果には「推定」ラベルを付け、確定と混同しない）:
tight crop を3-4x拡大して字形を見る。
- ウェイト(black/heavy/bold)、書体(角ゴシック/丸ゴシック/明朝)、角の丸み、ストロークの太さ均一性を記録
- **1フレーズ内で文字ごとに色を変える**ことがある（例「採用」=黒on黄、「する」=白、「？」=赤）→ これも記録
- **書体の特定は「系統が近い」で妥協しない**。字形の特徴（「さ」「り」「a」のカーブ、終端の形、ウェイトの太さ比）から実際のフォント名の特定を試みる（フォント識別サービス/字形比較/著名UGC編集アプリの既定フォント調査などで候補を絞り、複数候補をtight cropと並べて目視比較し最有力候補に絞る）。
- 特定できた書体が入手可能（無料配布 or 既に契約・保有しているライセンス）なら**そのフォントそのものを使う**。有料フォントで権利上使えない場合のみ、**字形を並べて視覚的に区別がつかないレベルの近似**を選定し、「なぜこれを選んだか（どの字形特徴が一致するか）」を記録する。
- 色・サイズ・行間・字間・縁取り/グロー等の装飾は実測値をそのまま使う。**「だいたい近い」「オリジナルでそれっぽく」は禁止**。実測できない値を埋める必要がある場合は、ユーザーに確認してから決める（独断で創作しない）。
- 完コピ適用後、参考動画のテロップとレンダリング結果を同一倍率で並べて目視比較し、書体・太さ・色・サイズ・行間が**識別不能なレベルで一致**しているかを検証する（`references/verification.md` 1.5節と同様、毎ラウンド確認しズレが残れば差し戻す）。

### 13. 多重チェック（分析の自己監査・★1サンプル/1手法で確定しない）
**実行可能ゲート**: `verify_analysis.py <ref_video> <audit.json>` を回す。色(3インスタンス照合+帽子/木目の罠ガード)・SE検出率(BGM判定込み)・サイズ分散を **PASS/WARN/FAIL** で出力し、WARN/FAIL が残る限り spec 化しない。audit.json には各色の検証インスタンス(時刻+ROI)とSE出現時刻を列挙する(スキーマは verify_analysis.py の docstring 参照)。
出現エフェクト/改行/逐語/フォントは目視主体なので、下記の観点で**複数例**確認する。各抽出値を**複数サンプル×複数手法**で相互検証し、既知の罠を潰してから spec を確定する。1フレーム・1回の測定で値を決めない（過去に色は帽子/木目で誤検出、SEは話し声で偽陽性、出現は前テロップ残像で誤判定した）。
- **色**: 同一テロップ型を**3インスタンス以上(別時刻)**で測る。中央ストリップsample＋tight-crop目視の**2手法一致**で確定。★罠ガード: 測定色が被写体の帽子(オレンジ~#F87F00, G>80)や木目壁(茶系)の色相に近ければ汚染を疑い ROI を絞って再測定。同型で色が割れたら「色が変わる」が実ルールか測定ノイズか判定
- **位置・サイズ**: 各型**3インスタンス**測り分散を確認。外れ値は前テロップ残像/重なりの混入を疑い再測定
- **タイミング**: zone-diff検出 × word-level文字起こし × フレーム目視 の**3系統で照合**。判定同期は2インスタンス以上で≤0.3s確認
- **SE**: 単一onsetピークで決めない。**テロップ同期(±0.15s) ＋ 外れ値(z>4)** の両立を必須に。BGM判定(HPSS harmonic継続)を先に出し持続harmonicをSE誤記しない。検出率(X/N)で「毎回か」を判断
- **出現エフェクト**: ピクセル計測 **と** フレームストリップ目視の**両方**で確認（計測単独は前テロップ残像に騙される）。立上りを2インスタンスで確認し hard-cut/fade を確定
- **改行/逐語**: 各型2-3例で確認。逐語/キーワードは複数テロップを発話と照合(1例で断定しない)
- **フォント**: 2型以上のcropで字形の一貫性を確認
- **合格条件**: 各値が「**3サンプル一致 ＋ 2手法/目視一致 ＋ 罠ガード通過**」を満たすまで spec に書かない。割れたら原因(汚染/ノイズ/実バリエーション)を特定してから記録

### 14. スペック化
`telop-spec.json`(機械可読・Remotionが消費)と `telop-spec.md`(人間可読・意図付き)を出力。上記すべてを含める。各値に「何インスタンスで確認したか」を残すと再現性が上がる。

### 15. テロップ完全一致プロトコル（★納品前・毎回・全要素。参考ごとに形態は別物）
テロップの形態（全画面カード型/字幕ロール型/ボックス型/逐次行型…）は**参考動画ごとに別物**。
過去案件の様式・このスキルの既定様式・Remotionテンプレの初期値を**持ち込まない**。毎回参考から
実測して再現し、納品前に**参考と出力の対応ビートのフレームを1対1で横並び照合**する。

**チェックリスト（全項目で「参考と出力が識別不能」になるまで反復）**:
1. **デザイン**: フォント（12節）/ 色（4節）/ 縁取り・グロー・影 / 背景ボックスの形状・角丸・不透明度
2. **サイズ・位置**: 文字高%（5節）/ ゾーン・中央/隅 / 行間・字間。**「小さく細い」は最頻の劣化方向**
   （実例: 参考=画面中央の極太全画面カードを、細い小組みで再現して差し戻された）
3. **タイミング**: 出現・消滅の発話同期（6節・≤0.3s）/ 表示時間 / 更新頻度（遷移数/分・verify_tempo.py）
4. **改行・意味単位**: 文節改行（10節）/ **意味ごとの表示グルーピング**＝何をひとまとまりで見せるか
   （1属性1行・文節キャプションの粒度。11節の逐語/キーワード判別を含む。
   「文の転がし表示」で文節をまたいだ改行が出ていないか）
5. **動的様式**: 入り方アニメ（8節）/ 逐次行 / 縮退 / 残留カード / SE随伴（9節）/ 判定テロップの階級
   （判定が通常キャプションと同格に見えていないか）

**照合方法**: 参考の各テロップ型につき代表ビートを選び、出力の対応ビートとフレームを抽出して
**1枚ずつ個別に横並びで目視**（montage/コンタクトシートでの提示は禁止・内部トリアージのみ可）。
1要素でも差があれば styles/テンプレ側を修正して再レンダー→再照合。
**参考に無い要素を足さない・参考にある要素を省かない**（フォント完全一致と同じ原則を全要素へ拡張）。

★**静止画一致だけでは「入り方」は検証できない**（実証: スチル全型一致で提出した出力が
「テロップの入り方が参考と違う」と差し戻された）。動的要素（8節: 出現アニメ・逐次行・縮退・
発話同期・更新リズム・意味単位の区切り方）は必ず**フレーム列（連続フレーム）として**参考と出力を
並べて照合する。`analyze_se_motion.py anim` の立ち上がり計測＋前後6フレームの目視を、
参考・出力の両方に対して行い、立ち上がり形が同じかを確認する。

## 成果物（telop-spec.json に含める項目）
- palette（色と用途）/ zones（ゾーン）/ telop_types（型ごとに size・position・highlight・**entrance**・**verbatim_or_keyword**・**line_break_rule**）
- **se**: { per_telop: bool, centroid帯, 種別ごとの差, bgm_present }
- **font**: { weight, style, rounded, per_char_color, closest_free }
- color_rules / timing_rules（判定≤0.3s 等）
- frames/ sheets/ crops/ anim_strip/ … 分析中間物（再現用に保持）

> 原則: **手順は再利用、数値・スペックは参考動画ごとに再分析**。SE/フォント/改行/逐語判断も参考動画が変われば必ず取り直す。
