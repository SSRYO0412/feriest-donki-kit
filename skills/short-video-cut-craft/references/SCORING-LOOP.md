# 採点ループ（[3.5] シート発行前の95点ゲート）— 正典

> 位置: [3]割当 の後・承認シート発行の前。**95点未満のままシートをユーザーに出さない**。
> 三大禁止の「自己採点禁止」に従い、採点者は Codex（`mcp__codex-cli__codex`・**model gpt-5.5必須**）。
> Claudeは設計者・修正者・反証者であり採点者ではない。

## 手順

1. **dossier を組む**（機械生成: 行構成・置かない判断・目視観察・機械検査結果）
2. **Codexに敵対採点を依頼**。プロンプト要件:
   - 役割「ショート動画の編集長」・忖度不要
   - ルーブリック固定: 意味整合30 / 全体構成・流れ25 / テンポ・尺感20 /
     正直訴求のセンス15 / 技術整合10（案件の性質で配点は案件プロファイル側で調整可）
   - 前提を明記: 総尺・素材本数固定・追加撮影不可・**実行不能な指摘は減点しない**・
     挿入尺下限などのシステム制約
   - 出力形式固定: 総合点 / 減点一覧（行・点数・根拠・具体的修正案） / 95以上なら
     「承認シートに進めてよい」と明言させる
3. **95未満なら修正ラウンド**:
   - 指摘を3分類する: (a)実行可能な編集改善 → 著述（author_ledger）へ反映して再ソルバ
     (b)**事実誤認 → 反証**（次ラウンドのdossierに根拠付きで明記。例: 「挿入はカット境界
     ちょうどで終わっている」） (c)素材制約で実行不能 → 前提に明記して再判定させる
   - **表記が誤解を生んだ場合はエンジン側の表記を直す**（18_R2実例: 行の発話表示が
     チャンク境界を跨いで実際より長く見えた → 50%重なりルールで修正）。
     採点者を騙すのではなく、誤読の原因を潰す
4. **再採点 → 95点以上まで反復**（上限5ラウンド。収束しない場合は残指摘を
   ユーザー判断事項としてシートに明記して提出）
5. 到達したら: 最終点・全ラウンドの指摘と対応を**修正記録DBに記録**し、
   実行可能なのに見送った指摘は承認シートのAI判定列に残す

## 禁止

- Claudeが自分で点数を付けて95と称する（自己採点禁止）
- 採点を通すための情報隠し（dossierには置かない判断・既知の弱点も必ず含める）
- 反証は事実（フレーム・時刻・検査結果）ベースのみ。「意図したから正しい」は反証でない
- 95に届かないままの黙ってのシート発行

ループが生んだエンジン改善: max_dur（尺を絞る著述）・window_pin（窓ピン留め）・

## 参照駆動モードの採点（3軸分離・2026-07-30確定）

参考分析シートがある案件（`REF-DRIVEN-SELECTION.md`）では、上記ルーブリック単独でなく
**3軸スコアカードで判定**する。採点セッションは軸ごとに物理分離:
- **A班 Codex×軸2**: dossierに参考の該当秒フレーム+style_profileを必ず同梱し、
  秒別横並びで差分を「素材差で当然/選定・編集で埋められる」に分類させる（埋残0秒まで）
- **C班 Codex×軸3**: **参考情報を一切渡さない**盲検ルーブリック
  （意味整合30/構成25/テンポ20/センス15/技術10は従来どおり）→ ≥95
- B班/D班（agy）: 盲検A/B識別テスト（軸2）・初見視聴の離脱予測（軸3）
- 合格条件: **3軸すべて合格**（軸1不合格0・軸2 Fidelity+肝3/3・軸3 ゲート0件+95点）。
  AI採点ループは本文と同じ**上限5R**（収束しなければ残指摘をユーザー判断事項として提出）。
  機械ゲートループは0件まで無制限（定義分離・2026-07-30決定）。
  従来の3分類（実行可能/事実誤認反証/素材制約）と修正記録DBへの記録義務はそのまま適用
- **審査員が参考を知らない絶対評価だけで95点を出さない**（18_R2停止点②の構造欠陥の根治）
