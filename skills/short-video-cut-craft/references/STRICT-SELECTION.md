## 大原則（Feriestで実測により確定）

1. **窓の適格性は final_spans に完全準拠**。窓の全フレームが使用可能区間に
   収まらなければ候補にすらしない（窓平均の採点は前半良く後半破綻を通す）。
2. **意味属性で事故を防ぐ**。ビートごとに意味条件をハードフィルタにする:
   - カーテン等の状態系: テロップと矛盾する状態(open等)を含む窓は禁止
     （実例:「キラキラ光っておしゃれすぎ」に開いたカーテンを当てた事故）
   - 内容系(床の星等): 該当属性を持つ標本を含む窓だけ
   - ★目視属性が使えない軸（主題=floor等をvisionが返さない）は**機械量で代替**する
     （床の寄り=床の星点の実測値順、日消え=輝度が低い窓優先）。属性の存在を確認してから設計する
3. **「微妙」（テイク内逸脱）は減点であって除外ではない**。より良い代替があれば負ける、
   代替が無ければ使う。ハード除外は合格カットを大量に巻き添えにする（実測15件/54件）。
4. **最終順位は絶対評価でなく相対比較（トーナメント）**。
   絶対評価「これは使えるか?」はCodexが繰り返し誤る（demo過大判定・シルエット誤判定・
   隙間の光を「開いている」と誤指摘）。相対評価「この枠にどれが最も合うか」は安定する。
   各枠の候補6〜8件を中央フレームで代表させ、1枠1回のCodex呼び出しで順位付け。
5. **絵変わり制約**: 隣接カットは異なる素材。素材が実質1本しかないビートのみ
   同素材を許すが窓を1秒以上離す（「絵変わりしない」指摘への対応）。
6. **組上げのフォールバックでも窓の重複だけは絶対に許さない**。
   制約を満たす候補が無いとき無条件に1位へ落とすと、同じ窓が2連続で置かれる
   （実際に起きた）。緩めてよいのは隣接同素材の制約だけ。候補が尽きたら候補数を増やす。

## ワークフロー

```
[T1] 候補抽出   select_final方式: ビート×枠ごとに全素材×全開始位置を走査し、
                final_spans適格 ∧ 意味属性適合 の窓をスコアリング
                （動き/パン目標・新鮮度・合焦・テイク逸脱減点）→ 互いに重ならない上位6〜8件
[T2] 相対比較   tournament方式: 枠ごとに候補フレームを1回のCodex呼び出しで順位付け
                （枠の要件・テロップ・rapid/product文脈をプロンプトに明記）
[T3] 組上げ     N案作るなら案kは第k位から繰り下げ。制約=①同一動画内の窓重複禁止
                ②隣接別素材 ③ビート固有並べ替え（床=床の星実測順・日消え=暗い順）
[T4] 機械検算   全カット×{使用可能区間内か / ユーザー却下区間と重ならないか / 窓重複}を
                全数列挙で0件確認。1件でもあれば設計に戻る
[T5] 出力検品   ★完成MP4から全カットの代表フレームを抽出して検品（設計JSONではなく出力物）。
                Codex一括検品→指摘は鵜呑みにせず親が現物を目視して真偽を切り分ける
                （実績: 指摘27件中、本物は2系統だけだった）
[T6] 記録       カット台帳へ全カット行（候補・順位・理由付き）、修正記録DBへスクリプト、
                採用が変われば動画台帳。即時・上書き禁止
```

## 検品時の切り分けの型（T5）

- Codexの指摘は**系統ごとに1枚現物を見て**真偽を決める。系統単位で誤検出することが多い
  （「カーテンの隙間から窓が見える」16件は全て商品の通常の見た目＝パネル間の光だった）
- 本物だった指摘は**機械量に翻訳して規則へ戻す**（床の寄り不足→床の星実測値順、
  明るすぎる日消え→輝度順）。同じ指摘を二度受けない
