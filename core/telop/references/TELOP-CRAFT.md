## [1] 区間定義 — テロップはショットと独立の時間区間

- **「1ショット=1テロップ」は必ず破綻する**。参考はショット途中で短い文言
  （「マジで」「最初は」等）に切り替わる。Dec28実績: 33ショットに対し35区間。
- 確定手順: ①全ショット×4点の帯切り出しを全数目視 → 文言が変わるショットを特定
  ②該当区間だけ0.1秒刻み全画面で切り替わり秒をフレーム確定
  ③隙間・重なりなしの連続被覆（0秒〜総尺）を機械検算。
- 機械スクリーニング: テロップ帯のフレーム間IoUを全フレーム測り、**低下点がショット境界から
  3F以上離れているものを全数実フレーム目視**する。フェード・手の遮蔽・行追加などの既知現象と
  「本物の欠落」は数値では区別できない（2605実績: 候補9件中、本物の欠落は1件=白発光遷移を挟む
  別テロップ「夕方鏡見ても」が丸ごとspecから落ちていた。ffmpeg版の納品候補にも残っていた）。
- spec の構造: `segments[] = {id, t0, t1, kind, rows}`。
  `rows` は行の配列、行は色分けセグメントの配列（**行内の色変化を改行と混同しない**）。
  `kind`: body（横書き本文）/ card（縦書きカード）/ vbig（縦書き特大）等、様式が別物のものだけ分ける。

## [2] 様式実測 — まず種別を分類し、定常フレームで測る

### ★[2-0] 種別の階層分類（2026-08-09 案件F で確立・省略厳禁）

**参考のテロップは1種類ではない。1枚だけ見て様式を決めると必ず指摘される**
（実例: 13区間を全部同じ書式で作り「参考のテロップは一個だけじゃないの分かってる？
カットごとに変えているし強調エフェクトなども入れている。全然分析足りていなくない？」）。

手順（実測で機能した順序）:
1. **全区間の書体・サイズ・本文を一覧にする**（prproj があれば `prproj_telop_dump.py` で機械抽出）
2. **サイズが跳ねている区間＝別種別**。その区間だけ画像を並べて役割を目視裁定する
   （書体・サイズは機械で取れるが、**「どの区間がどの種別か」の役割は目視でしか裁定できない**）
3. spec / telop_ledger に **`種別` 列を必須**で持たせる（通常/感嘆/商品名… 案件ごとの語彙で）
4. 種別ごとに様式（書体・サイズ・色・装飾）を別々に確定する

実例（参考うどん・3階層）: 通常=`mplus-1p-heavy` 68.948 白 ／
感嘆・言い切り=**明朝極太 `HeiseiMinStd-W9`** 109〜129 ／
商品名2行組=上段68.948白＋**下段115〜161・色は素材そのものの色を画素実測**
（明太`#EAB1A3`・から揚げ`#EFE919` 等。名前で色を決めない）。
**フチも純黒とは限らない**（実測 `#3C3934` の暗いグレー）。

- ★機械マスクは被写体の色に汚染される（実例: 食材の `#E4AF4A` を高さ400〜800pxで拾った）。
  **色と役割の最終裁定は帯を並べた目視**。
- 参考より文字数が多い区間はサイズを落とさざるを得ない＝**強調が参考より弱くなる**。
  その旨を明示してユーザーに判断を仰ぐ（黙って弱いまま出さない）。

- ★**サイズ・位置は必ず「動きが止まった定常フレーム」（区間の中盤以降）で測る**。
  出現アニメの途中フレームを測った値をレンダラーに焼くと、24%小さい等のズレに気づけない（実害あり）。
- ★**フチの太さ・グローは「書き出した動画」でしか合わない**。PNG単体で合わせた値は
  背景合成と圧縮でズレる（stroke=5がPNGで一致→動画では0.75倍。補間して7が正解だった）。
  レンダー→書き出し→白フチ/黒芯比を参考と比較→補間、で決める。
- ★出力と参考の突合は「帯を上下に並べた画像の全数目視」が最終裁定。機械のbbox比較は
  背景の白い服・箱・シートマスクで汚染され全区間偽陽性になり得る（2605実績: 38/38偽陽性）。
  自作PNG（クリーン側）をテンプレートに参考フレームへフィットする方法も、書体代替がある案件では
  hitが0.3-0.5に沈み信用できない。数値は絞り込みに使い、裁定は目視。
### ★参考の `.prproj` があるなら書体・本文・サイズは機械で取れる（2026-08-08 確定）

下の目視手順は「参考が動画しか無い」場合のもの。**参考の `.prproj` が手に入るなら、
本文・フォント名・フォントサイズは解析で確定できる**ので、目視で当てにいかない。

```bash
# ★Premiere を閉じてから。読み取り専用
python3 ~/.claude/skills/premiere-bridge-ops/scripts/prproj_telop_dump.py 参考.prproj
```

実案件（320ブロブ）で **本文303件・フォント名302件**を取得できた。
ユーザー提供の正解値（サイズ69 / 塗りFFFFFF / フチ313131 / シャドウ090000）と突合し、
本文・`HiraginoSans-W6`・サイズ`68.948` が一致。同一様式の他5枚でも再現した。

- `.prproj` は gzip 圧縮XML。テキストは `<StartKeyframeValue>` の base64
  （FlatBuffers・マジック `44 33 22 11`）。文字列は `u32の長さ + UTF-8平文`
- **★フォントサイズは整数ではない**。UIが四捨五入して `69` と表示していても内部は `68.948`。
  整数で grep すると見つからない
- **色だけは自動確定できない**（float の 1.0/0.5 が色に化ける・暗い色が整数と区別できない・
  `ff ff ff` がパディングとしても出る）。色は従来どおり画素実測する
- **ライブのExtendScript/UXPからは本文もフォントもサイズも色も一切読めない**。
  Adobe が「ExtendScript API は AE 製 .mogrt 向けの設計」と明言している仕様であって、
  やり方が悪いのではない。ここを探しに行かないこと

### 書体の特定（2605で確立・参考が動画しか無い場合）
- **分類はブロック単位で決めない**。「前半は筆・後半はゴシック」のような大づかみな割り当ては必ず
  例外を取りこぼす（2605実績: 38区間中3件が誤判定。うち1件は白発光の遷移をまたいで書体が変わっていた）。
  **全区間を原寸で1枚ずつ見て割り当てる**。
- 候補選定は「欠字なし」が先。字形が最も近くても常用漢字が欠けていれば使えない
  （HOT-Kointaikk は字形一致だったが「湿」「崩」が無く不採用）。
  `font.getmask(ch).getbbox() is None` で必要文字を全数チェックしてから比較に進む。
- 比較は**本番と同じフチ付き・同じ行幅**に揃えて並べる。素の字形だけ見ると太さの差を見誤る。
- ★**カウンター（字の内側の空き）が潰れるかは書体だけの問題ではない**。PILの `stroke_width` は
  外側だけでなくカウンターにも回り込むため、画数の詰まった字（毛・鏡・撮 等）は太いフチで塗り潰される。
  対処は順に ①マスク方式にして1px細らせる ②その字を含む区間だけ書体を差し替える。
  判定は「白/黒ラン比」を参考と比べる（2605: 参考0.73に対し出力0.50＝黒が太すぎた）。
- 色は名前で決めず芯を実測する。「黄色」に見えても参考は R243 G226 B139 の淡いクリーム黄で、
  彩度の高い (255,214,41) とは別物だった。アンチエイリアスを除くため MinFilter で内側だけ測る。

- 測定マスクの使い分け（1080x1920想定・値は毎案件で再調整）:
  - 黒芯+白フチ: `bright=(min>225)` を MaxFilter で膨張 → `& (max<60)`
  - ピンク: `r>165 & g<135 & b>105 & r-g>55` ／ 水色: `b>195 & g>165 & b-r>22`
  - 白文字: `min>248`
- 段組みの規則（参考ごとに再実測。Dec28の実測値は初期仮説として使える）:
  - 本文は中心固定（2行までは中心そろえ、3行目は下に足す）
  - **絵文字行（国旗等）は行数に算入せず「本文の上に足す」**（算入するとブロックが下がる）
  - 注釈行（*1…）は本文直下に小さく（本文と同ピッチで足すと大きすぎ・下すぎになる）
  - 強調行（価格等）は本文と別サイズ・別位置のことがある → 区間ごとの OVERRIDE 機構を持つ

## [3] 動き実測 — テンプレートマッチングが唯一信頼できる

背景が動くため**画素差分・面積比は全て交絡する**（面積比検出器は35区間で8件の偽陽性）。

```python
# 区間中央フレームのマスクをテンプレートに、各フレームで (dx,dy,scale) をフィット
# テロップは不透明 → 背景がどう動いてもテンプレートの形は不変
# 高速化: 点を2000に間引き、粗探索(4px/6段階)→細探索(1px/5段階)の2段
# 判定: 出現後(一致率>0.75)のフレームだけで dx幅/dy幅≥6px or scale幅≥0.05
```

### 測定器の罠（すべて実際に踏んだ）
1. **探索上限に当たった値は「不一致」の印**。scale上限1.26で探索して1.605倍のポップを
   「静止」と誤判定した。結果が探索範囲の端に張り付いたら範囲を広げて測り直す。
2. **ffmpeg の `-ss` 入力シークは1フレームずれる**。数フレームの出現アニメを丸ごと見逃す。
   フレーム取得は必ず `select='eq(n\,N)'`。
3. **時系列の形でノイズと本物を分ける**。dyの符号が毎フレーム反転=量子化ノイズ。
   本物は三角波（等速往復）や減衰振動の滑らかな形になる。
4. **何が動いているかの切り分けは全画面で**。帯の切り抜きだけ見ると
   「画面全体がブレている」と「テロップだけが巨大→縮む」を混同する（実害: 画にエフェクトを掛けた）。
5. 拡大中心はテロップ中心とは限らない。**中心座標の時系列が動く方向**で同定する
   （y中心が下へ動く=拡大中心はそれより上=フレーム中心、等）。

### キー値への変換
実測px系列を**定常値で割って%**にする（例: 幅569→913→569 = 100→160.5→100%）。
フレーム時刻は F=1/fps の整数倍でそのまま打つ。

## [4] 実装

### [4]A MOGRT 方式（★既定・2026-08-09〜）

正本アセット: `premiere-bridge-ops/assets/telop_3slot_v22.mogrt`（本文＋49項目・1レイヤー・
フォント編集解禁済み・**色は 0〜100 の数値スライダー3本で指定**）。
v20 はカラーピッカー方式でスクリプトから色を触れない旧版。**必ず v22 を使う**。

- 入力は telops.json（[2]の spec: 本文・種別・書体・サイズ・色・強調スロット・t0/t1）。
  配置とパラメータ投入の定型は `premiere-bridge-ops/templates/pr_place_mogrt.jsx`
- **本文を変えたら `fontTextRunLength` を文字数に揃える**（揃えないと setValue は成功し
  読み戻しも通るのに、UIで開いた瞬間に Premiere が落ちる）
- **EGP のスライダーは Premiere 側で 0〜100 に丸められる**（255→100）。数値は全部 0〜100 に収める
- 書体はその環境に**実在する PostScript 名**を指定（未インストールは AE も Premiere も
  警告なしに代替する。着手前に `~/Library/Fonts`・Adobe Fonts を実際に見る）
- **★MOGRT の素材長は 150F（5.000秒）**。`clip.end` で超えて伸ばすと **150F 以降は無言で
  描画されない**。しかも**読み戻しでは検出できない**（クリップは伸びて見える）——
  書き出した画素で初めて分かる。長い区間は **複数枚を隙間なく敷き詰める**
  （実例: 337F を 0-150 / 150-300 / 300-337 の3枚で被覆）
- 文字単位のグロー・部分下線は不可 → **行を分けて別クリップ**。強調は3スロット
  （色/大きさ/縁色/縁太さ/縦オフセット）の範囲でやる
- 約物の詰め送りはトラッキングで近似し、`sourceRectAtTime` と**書き出した実測幅**で補正
- **絵文字は MOGRT/フォントに頼らない**。豆腐・代替化けの恒久回避は
  **絵文字PNG（例: `1f447.png`）を別クリップで重ねる**（参考うどんの「※詳細は　をチェック！」も
  全角スペースに👇画像を重ねる作りだった）
- 露出項目は後から増やせない（増やす＝テンプレ作り直し＋配置済みクリップ差し替え）。
  テンプレ設計時に「なし」を含めて余裕を持たせる

検証は [6] と同じ: `sourceRectAtTime`（レイアウトエンジンの実寸＝自分の書き戻しにならない）で
中間測定し、**最終判定は書き出した MP4 の画素**。

### [4]B PNG レンダー（廃止・保守参照用）

> **新規案件では使わない**（2026-08-09 ユーザー指示）。既存 PNG 方式案件の保守と、
> Pillow 描画の知見（ロゴ縮小・base/emph 分離の考え方）の参照用に残す。

- 出力は区間ごとの全画面透過PNG（`T01.png`〜）。1版=1ディレクトリ（telop_png_vNN）、
  **pyは上書きせずvNNで新規**、先頭docstringに「何をなぜ変えたか」を積む（後の精読を可能にする）。
- 約物の詰め送り: 「」（）、。は約0.55emに詰める（全角送りのままだと行が最大12%長い）。
  開き括弧は前アキも削る（グリフが枠の右寄り）。**行末の句読点は「送り」を直しても絵が動かない**
  （次の文字がない）→ 位置そのものを直す。
- 縦書き: 読点は文字枠の右上。明朝はW3では細すぎることが多い（ttcのindex指定でW6等を選ぶ）。
  Apple Color Emoji はサイズ160でしか開けない→描画後に縮小。
- グローは「芯（小半径×高gain）+ 広がり（大半径×低gain）」の二重掛けで初めて参考に届くことがある。
  逆に締めるべき場合もある。強度1パラメータではなく2パラメータで合わせる。
- **★ロゴ等の画像を縮小するときは `Image.thumbnail()` を使わない**。JPEGに対して内部で
  `draft()`（JPEGのDCT段階での粗い縮小）が先に走り、大きな縮小率で輪郭が階段状になる。
  実例: 957px→124px でクライアントロゴがガビガビになり指摘を受けた。原因はエンコードではなく
  **PNG生成時**だった（書き出し前後の差は輝度2.7・彩度4.4しかなかった）。
  `resize(..., Image.LANCZOS)` を明示し、縮小率が大きいときは
  **一度2倍の中間サイズへLANCZOS → もう一度LANCZOS** の2段にする。
  同じファイル内で絵文字だけ LANCZOS を明示しロゴが抜けていた＝**縮小箇所は全数grepで洗う**。
- 小さく出るロゴは**表示サイズ自体**も疑う。124px四方では社名の文字高が20px程度しかなく、
  どれだけ綺麗に縮小しても限界がある。
- **部分強調（行・単語だけ動かす）= base/emph 分離レンダリング**:
  描画関数に `keep(通し文字番号)->bool` を渡し、False の文字は**送りだけ進めて描かない**。
  base（対象抜き）と emph（対象だけ）の文字位置が完全一致し、重ねれば元の絵に戻る。
  検算: `alpha_composite(base, emph)` と元PNGの最大画素差（0〜数値小ならOK）。
  ただし**強調語と非強調語が同じ行で隣接する場合、フチの重なり順が変わるので差が出る**
  （実測221）。これは欠陥ではない。Premiere上の合成順（base→emph）とは一致するため、
  一体レンダーではなく **base+emph の合成結果**を正とする。書体を変えて字間が空くと差は0になる。

## [5] Premiere 配置+アニメ

- テロップは MOGRT クリップ（[4]A）を時間指定で敷く（旧PNG方式は V2 に敷いていた）。
  **★ネイティブテキストはどの経路からも作れない（2026-08-03 全経路を潰して確定）**:
  | 経路 | 可否 | 根拠 |
  |---|---|---|
  | ExtendScript | ✗ | テキストクリップの生成APIが存在しない |
  | UXP | ✗ | Adobe公式が「テキストレイヤーはUXP未対応」と明言。MOGRTパラメータも読み書き不可 |
  | QE DOM | ✗ | `QEProject` の生成メソッド一覧に title/text/graphic が無い |
  | レガシータイトラー(.prtl) | ✗ | Premiere 23.0（2022年10月）で廃止 |
  | **MOGRT** | **◯（唯一の道・既定）** | AE 製のみ有効（`getMGTComponent()` が null でないこと）。v22 で本文/書体/サイズ/色/強調まで指定可 |
  | prproj のノード移植 | ✗ | 実装して失敗。TrackItemは1トラックにしか属せず、複数シーケンスへ配線すると壊れる |
  **既存テロップの「文言だけ」なら prproj の gzip XML 内 base64（FlatBuffers・`u32長さ+UTF-8平文`）
  を直接パッチして書き換えられる**（新規生成はできない）。この判断に時間を溶かさないこと。
  強調 emph は V4、光の帯等のFX素材は V5 に。
- ★**カットはフレーム格子に乗せる**（2026-08-09）。設計秒をそのまま入れるとカット間に
  サブフレームの隙間ができる。フレーム単位で敷き直す（実例: 28/58/76/65/55/55F＝計337F）。
- ★**1フレームの穴は全トラック終端の機械検算でしか見つからない**。あるトラックの最終カットだけ
  1F 短い事故は目視では絶対に分からない。**全トラックの `clips[last].end` を並べて比較する検算**を
  毎回入れる。
- ★**`縦横比を固定` の既定は false**。`スケール(高さ)` だけ動かすと縦に伸びるだけでズームに
  ならない。参考同様 true にしてから倍率を打つ（実測で設計と相関 0.996〜1.000 を確認済み）。
- 縦型シーケンスはスクリプトで作れる（`seq.getSettings()`→width/height/frameRate/PAR/editingMode を
  設定して `setSettings()`。定型は premiere-bridge-ops `EDITING-MATRIX.md`）。
- **調整レイヤーはスクリプトから作れない**。参考が調整レイヤーでズーム/Lumetri を掛けていても、
  **同じ効果を各カットのクリップへ直接掛ければ絵は等価**（テロップより下という重なり順が同じため）。
- ★**overwriteClip の罠**: 静止画を remove→overwriteClip し直すと**既定尺(5秒)で後続を潰す**
  （実害: 35枚→31枚）。時間順に敷き詰めるときしか安全ではない。
  → **「トラック全消し→全枚数敷き直し→全アニメ付与」を1本のスクリプトに集約**し、
  以後の修正はそれを再実行する。検算: 枚数=設計数・区間ズレ0・隙間0。
- ★キーフレームは `OFF=clip.inPoint.seconds` 基準（静止画は3600秒付近）。
  検算で「最初のキーが inPoint〜outPoint 内」を全クリップ数えて0件確認（`_video-core/PRINCIPLES.md` §12）。
- PNG差し替え後は `projectItem.refreshMedia()` 必須（パスでキャッシュされる）。
- エフェクトのプロパティ名は**決め打ちせず必ず列挙してから参照**
  （半角カナ登録「ｺﾝﾎﾟｼﾞｼｮﾝのｼｬｯﾀｰ角度を使用」、「スケール (高さ)/(幅)」分裂等）。
- 使えるエフェクトは `qe.project.getVideoEffectList()` で列挙して探す
  （2605ではこれで「VR デジタルグリッチ」を見つけてグリッチ指示に使った）。
- `proj.getInsertionBin()` は null を返しスクリプトごと落ちることがある。`proj.rootItem` を使う。
- **プロジェクトは他セッションや手動操作で閉じられる**。`app.projects` を列挙して無ければ
  `app.openDocument(path)` で開き直す（作業中に実際に閉じられた）。

### 画角調整（ffmpeg側）の罠
- `scale=W*Z:H*Z, crop=W:H:x:y` の **y は「拡大後の高さ−H」で頭打ち**になる。
  1.25倍なら最大480px。それ以上の値を渡しても同じ絵にクランプされ、**数値を変えても絵が動かない**。
  上げ幅を稼ぐには倍率自体を上げる必要がある。必要倍率は連立で解く:
  `src_y*Z - H*(Z-1) <= 目標y` → `Z >= (src_y - 目標y) / (H - 目標y)`
- テロップを避ける位置は**テロップPNGのink上端を実測**して決める。2段階表示なら
  最終形（行数が多い方）の上端が基準（2605: 1行版y910 / 2行版y855 → 855で計算）。
- 対象物は時間とともに動く。**全フレームの最下端**で判定する（1フレームだけ見ると外す）。

### 分割画面（左右/上下）
- 各素材を half幅×全高 に切り出して `hstack`（上下なら `vstack`）。色は他カットと同じ正規化を通す。
- 切り出し中心は素材内の被写体位置に合わせる（中央固定だと端の対象が見切れる）。
- 分割線は参考に無ければ入れない。入れるなら `drawbox` で境界に。

### PNG/キーで作れないものは「素材」にする（2605で確立）
光が走る・線が動く・線が描かれる、は Premiere のキーでは作れない。Pythonで連番を作り
**ProRes 4444（アルファ付き）**にして別トラックへ置く。作り方の型:

| 作るもの | 方式 | 実測で合わせるもの |
|---|---|---|
| キラン（光が走る） | テロップPNGのアルファをマスクに、ガウシアン帯を左→右へ通す | 帯の太さ・傾き・通過フレーム数。**明度パルスでは光が走らない** |
| 集中線 | 放射線を描き中心を抜く。ゆっくり振れ＋明滅 | **中心からの相対距離ごとの白画素率**を参考と突き合わせる（帯ごとに比較） |
| 描き進む線（矢印等） | 参考から線のマスクを抽出→上端からBFSで測地距離＝描き順→距離≤t*maxだけ出す | 出現フレームと描き終わりフレーム。**描き終わり後は最終フレームを保持**して区間末まで出す |

- マスク抽出は閾値を振って**1連結成分になる値**を探す（2605の矢印は閾値242で5919pxの単一成分）。
- 素材の尺は区間長で決める。区間16Fに14Fの帯を置くとはみ出す。
- ★**マスクの範囲は行の実測から決める**。「2行目だから y960以降」のような当て推量は外す
  （S15は国旗行があり3段構成で、案件S製品!は y912-1002 だった＝範囲外になり効いていなかった）。

### エフェクト実測値（Premiere 2026 日本語UI）
| 目的 | 手段 | 実測の勘所 |
|---|---|---|
| 放射状ブラーで飛び込み | トランスフォーム＋シャッター角度360＋スケール480→100%(8F) | Premiereに放射状ブラーは無いがこれで代替できる |
| 横ブレ | 方向ブラー 角度**90°**が横（0°は縦） | 適用量は効きが強い。14でも読めない、6で「読めるブレ」。必ず書き出して決める |
| 白フラッシュ | プロセスアンプ 明度 55→0 | スケールの打ち込み(118→100)と併用で「打ち込み」になる |
| ふるえ | 位置キー ±9px/±7px を斜め交互に減衰、10Fで停止 | 正規化座標: dx=px/1080, dy=px/1920 |
| キラリ（光が走る） | **明度パルスでは光は走らない**。文字アルファをマスクにしたガウシアン帯(斜め傾斜)をProRes4444アルファ付き素材として生成し左→右に通す | フチ・グローに乗せず文字面だけ(mask<0.8→0)。発話の頭を避けて数F遅らせる |

### ★納品済みプロジェクトから採った実測レシピ（2026-08-08）

参考の `.prproj` からキーフレームを直接読み出したもの。**そのまま打てば同じ動きになる**。
キーフレーム時刻は `clip.inPoint.seconds` を引いた**相対秒**（静止画は inPoint が約3600秒）。

| 演出 | 実装 | 実測値 |
|---|---|---|
| **白フラッシュ** | `プロセスアンプ` の**明度**（既定0）を上げて戻す | `0.000s=100 → 0.100s=80 → 0.200s=35 → 0.333s=0`（10F） |
| **弾性バウンド** | モーション **スケール** 16キー | `35.5→61.5→96.5→114→121→111→101.5→91.5→93→96.5→100.5→104.5→104→103→101.5→100.5`（0.5秒/15F・3回振動して収束） |
| **ジッター** | モーション **位置** 17キー | ±0.002程度の微振動（正規化座標） |
| **小ポップ** | モーション スケール3キー | `96.6→104.2→100` |
| **キラン** | **エフェクトではなく動画素材**を別トラックに0.46秒重ねる | Premiereはスクリプトからマスクを作れないため、エフェクトでは作れない |

- **白フラッシュのカーブは等速ではない**。前半3Fで20しか落ちず、後半4Fで35→0。
  「パッと光ってスッと引く」感じはこの偏りで出ている
- **明度100は白飛び**。アルファは効いたままなので**文字の形を保って白く光る**
- **装飾は全区間に一律で置かない。** 実測した納品物ではテロップ8枚のうち
  **白フラッシュは1枚だけ**だった（置かない区間があるから置いた区間が立つ）
- 強調(emph)は base と**別トラックに分離**され、動きは emph 側だけに付いていた

これらは **クリップの種類を選ばない**（実写・PNG・ネイティブGraphic・MOGRT のどれでも同じ）。
参考プロジェクトから読んで別プロジェクトへ**丸ごと移植できる**
（手順は skill `premiere-bridge-ops` の `references/UI-EQUIV.md`）。

### 出現アニメの基本型（参考実測から）
- 等速ポップ: 100→160.5→100%（三角波・8F）。上段が動かないなら行を分けてキーは下段だけに
- 弾性バウンド: 44→114.6→86.1→100%（減衰振動・12キー）
- 小ポップ: 96.6→104.2→100%（7F）
- ポップイン+オーバーシュート: 35→118→88→100%等、実測カーブをフレームごとにそのままキーへ
- ランダムジッター: カード等が毎フレーム±10px弱で震え続ける。実測した毎フレームのオフセットを
  そのまま位置キーに打つ（乱数で作り直さない）
- 白発光の解け（クロス遷移）: 前テロップ消灯→新テロップが真っ白で立ち上がり通常表示へ。
  不透明度の立ち上がり＋プロセスアンプ明度100→0で再現
- 参考が静止なら**動きを足さない**（動きの捏造をしない。31/35区間は静止だった）

## [5.5] カットの差し替え — 意味が同じものを素材DBから探す

テロップ工程と同じ案件で必ず来る依頼。手順を型として残す。

- **指定フォルダがあるときは全窓を機械で走査**してから目視する（2605: 0618フォルダ1141窓）。
  `demo_flag=1`（実演あり）で絞ると、提示だけの窓が落ちて候補が数十本になる。
- ★**説明文の全文検索は否定文を拾う**。「塗る・開ける動作は確認できない」が「塗る」で
  ヒットするため、キーワード検索だけで候補を決めない。`demo_note` を読んで裁定する。
- 候補は**実フレームを見て決める**。DBの説明は検索の索引であって合否の根拠ではない。
- **同一クリップの二重使用を機械で止める**。別カットの差し替えが芋づるで重複を生む
  （2605実績: S20をC1374にしたら、既にC1374だったS19と同一クリップになり「全く同じ絵」になった）。
  差し替えのたびに使用クリップ名の重複を数える。
- **前後のカットと場所・動作が重ならないように置く**。隣接カットの画素差を測って
  25以上あるかで機械確認できる（似ていると20未満になる）。
- 尺が足りるかは**確定窓の長さ**で判定する。隣接窓が連続していれば繋げて使える。
- 「引けば商品が分かる」は誤り。2605では引くと**何をしているか却って読めなくなり**、
  顔の寄りの方が伝わった。寄り引きは必ず両方作って見比べる。

## [6] 検証 — 書き出した実ファイルの画素で

- **完了判定は常に書き出したMP4**。参考に使った測定器をそのまま出力にも掛けて数値突合
  （例: バウンド全フレーム差6px以内、ポップ幅比1.047一定）。
- 毎レンダーの固定検算: 総フレーム数・総尺・色空間(bt709)が参考と一致。
- 機械検出器の異常値は**実フレーム目視で裁定してから**直す（偽陽性が多い。8件中本物2件の実績）。
- 版管理: MP4・py・jsxとも上書き禁止。却下版も残し、台帳の `render_db` に
  1レンダー=1行（採用状態・却下理由・検算値・罠の記録）。
- ★**却下した版とその理由をスクリプトのコメントに残す**。ユーザーが「さっきの方が良かった」と
  戻すことがあり、履歴が無いと同じ試行を繰り返す（2605の分割画面は 寄り→引き→引き調整→寄りに復帰）。

### 納品前の固定検品（2605で確立）
1. **規格**: 総フレーム数・尺・fps・色4項目（space/primaries/transfer/range）・音声が参考と一致
2. **全区間**: テロップ帯のインク量で描画欠落ゼロ
3. **全フレーム**: 縮小してグレー1パスで読み、輝度の最小・最大から黒落ち/白飛びを検出。
   異常値は**必ず実画を見て裁定**（黒背景カードなど設計どおりの黒がある）
4. **隣接カット**: 画素差が25以上（似ていると重複に見える）
5. **素材の重複**: 使用クリップ名を数えて2以上が無いこと
6. 変更した箇所を参考と並べて目視

### レンダーの運用
- ユーザーが自分でタイムラインを確認する段階では**書き出さない**。素材を差し替えて
  `refreshMedia()` するだけにし、確認は「素材にテロップPNGを合成した静止画」で見せる。
- 納品用はフル解像度のみ。確認用の圧縮版は納品段階では作らない。
- 送付が `Socket is closed` で失敗したら解像度を落として再送（30MiB前後が上限の目安）。

## ★演出は「意味の段階」で設計する（一律付与は必ず差し戻される）

全区間に同じ色・同じアニメ・同じエフェクトを当てると
「**全部同じになっている。意味に応じて変えて**」と指摘される（2026-08-03 実例）。

**装飾を置かない区間を意図的に作ることで、置いた区間が立つ**。はしごの例:

| 位置 | 意味 | 色 | アニメ | エフェクト |
|---|---|---|---|---|
| フック | 掴み | 白のみ | なし | なし |
| 反復 | 事実提示 | 白のみ | なし | なし |
| 商品名 | **ここから始動** | 色ベタ | なし | 白フラッシュ |
| 山1 | 訴求の核 | 白＋強調色 | ポップイン | キラン |
| 山2 | 質感 | 白＋強調色 | 小ポップ＋揺れ | グロー |
| 溜め | 谷 | 白のみ | **なし**（動かすと溜まらない） | なし |
| オチ | 最大 | 白＋強調色 | ポップイン | キラン＋グロー |

- **エフェクトは意味が立つ区間に限定する**。「キラン」は光を語っている区間だけ。
  全部に付けると意味が死ぬ。
- 揺れ等の強度は**必ず1往復の調整を見込む**。初回は強すぎになりやすい
  （実例: 頭9px/毎フレーム交互 → 「大きすぎ」→ 頭4px/2フレーム毎で確定）。
- 参考が2枚に割って畳みかけている箇所は**尺比まで踏襲する**
  （参考 1.57s:0.77s = 2.04 → 制作 1.53s:0.77s = 2.00）。
- **明るい背景に置く文字は「白フチ」が溶ける**。黒文字＋白フチだけでは読めない。
  外周にもう一段暗いフチを足した**3層（暗フチ→白フチ→本体）**にすると、色を変えずに輪郭が立つ。
- **三点リーダ「…」はグリフが字枠の左寄りに入る**ため、含めると中央揃えの重心が右にずれる。
  中央揃えを優先するなら削る判断もある。

## 心得
- 要求（何が出て・いつ切り替わり・どう動くか）は**参考のフレームから**決める。テロップの文字・
  切り抜き・途中フレーム・検出器の数値だけから決めた仮説は全て実害を出した。
- 合わせ込みは「レンダー→書き出し→実測→補間」のループ。PNG上の一致で満足しない。
- 修正のたびに新版・理由をdocstringに積む。この履歴が次回の精読と学び抽出を可能にする。

## ★縦組みテロップ（2026-08-06 案件U（ホラーイベント）公式PVで確立）

日本のホラー/シネマティック系の参考動画は、冒頭のフックだけ**縦組み特大**という別階級を使うことが多い。

### 実測して決めること

参考の定常フレームで、白マスクと赤マスクを**別々に**取って測る。

| 項目 | 実測例（1080×1920） |
|---|---|
| 列中心 x | **555（画面中心540とほぼ同じ＝中央揃え）** |
| 字送り | 172px |
| 字高 | 165px |
| 本編との階級差 | 本編51px に対し 3倍以上 |

★**列中心はカードごとに散らさない。** 全カード共通で画面中央に置く。
左右にばらけていると「中央に来てない」と即座に見抜かれる（実際に指摘された）。
タイトルと添え書きを並べる場合は、**2列を「対」として群の中心**を画面中央に合わせる。

### ★長音符・括弧は90度回転しないと横倒しになる

縦組みで `ー 〜 （） 「」 …` をそのまま描くと横向きのまま残り、
「案件U（ホラーイベント）」が「案件Uホラー ハウス」に割れて見える（実際にこれで一度出した）。

```python
ROT_CHARS = set("ー－—–〜～（）()「」『』【】…‥")

def draw_char_vertical(canvas, ch, cx, cy, font, fill, fs):
    tmp = Image.new("RGBA", (fs*2, fs*2), (0,0,0,0))
    # ...文字をtmpの中心に描く...
    if ch in ROT_CHARS:
        tmp = tmp.rotate(-90, resample=Image.BICUBIC)
    canvas.alpha_composite(tmp, (int(cx-tmp.width/2), int(cy-tmp.height/2)))
```

句点「。」も縦組みでは右上に来るのが正しい。位置を作り込めないなら**入れない方が自然**。

## ★テロップの文言＝VOで喋る言葉そのもの（2026-08-06）

参考を測ると、テロップは**VOの発話をそのまま分割したもの**だった。

> VO「壊れた設備は／どこか遠くから聞こえてくる／ピアノの音が不気味で」
> テロップ「壊れた設備...」→「どこかから聞こえる」→「ピアノの音が不気味」

**別々の文章を並べると「内容が入ってこない」**（実際にこの指摘を受けた）。
テロップとVOで違うことを言うと、視聴者は読むか聴くかのどちらかを捨てる。

### 実装ルール

- テロップ文言を先に決め、**VOはそれを繋いだ自然な文**にする（逆でもよいが必ず一致させる）
- **VOの発話開始 ＝ 対応する先頭テロップの開始時刻**（参考は平均0.16秒以内で一致していた）
- 1つのVO文が2〜3枚のテロップをまたぐのは正しい。テロップの方が細かく切り替わる
- 固有名詞はVOで読ませない（TTSのイントネーションが崩れ誤読も出る）。**名前はテロップとキービジュアルが担う**

### 検証

完成品の音声を文字起こしして、**全VOがテロップと同じ言葉・同じ時刻**で聞き取れることを確認する。
ミックス後に確認するのが肝（BGM/SEに埋もれていないかも同時に分かる）。
