# 修正・再レンダー チェックリスト（毎回開いて1項目ずつ潰す）

## A. 着手前（1件でも未実施なら編集に入らない）

- [ ] **管理DB（動画台帳）で現在の採用MP4・採用py・採用vを確認した**（会話・mtimeを根拠にしていない）
- [ ] ★**修正台帳（Notion）の全行**を読んだ。`修正指示` 列が空でない行を1行も飛ばしていない（`REVISION-LEDGER.md` §5.1）
- [ ] **修正指示DBの未完了行**（ステータス≠納品済み/却下/保留）を読んだ。対象動画名・対象秒数・修正種別・指示内容を原文で確認した
- [ ] 指示が曖昧な行は**着手前に1問だけ聞いた**（推測で作って作り直すより安い）
- [ ] **その動画の過去修正の差分表**を作った（過去に直した項目の一覧: 音声/BGM/テロップ/カット/顔クロップ/1フレーム修正…）→ 今回の修正で戻してはいけないものを明文化した
- [ ] 対象カットを特定した（カット台帳/素材使用DB → cut id・素材rel・素材tin・尺・意図・顔/クロップ方針）
- [ ] 素材DB側の制約（顔NG・BGM混入・禁止秒数・使用不可素材）を確認した
- [ ] 編集計画を書いた: どのcut idを触るか／映像・音声・BGM・テロップのどれか／保持する既存修正／新規出力ファイル名（v番号込み）

## B. 実装

- [ ] **py/sourceから再レンダー**している（完成MP4の直接パッチをしていない）
- [ ] 出力は**新規v番号の新規ファイル**（上書きしていない。失敗版も残す）
- [ ] **該当カットだけ**触っている（指摘外のカット・全体クロップ・全体音声/BGM差替をしていない。必要なら理由を先に出して確認）
- [ ] 音声は**VO単体+共通BGM頭出し**で再ミックス（BGM入りMP4音声の流用をしていない）
- [ ] CTA音声の差し替えは開始位置まで管理した（直前の元音声の重複語を確実に消してから新CTAを入れた）
- [ ] 音声の違和感が2回続いたら編集で粘らず再生成した（声質モデルは案件指定に固定）
- [ ] 顔クロップは**カット単位**（全体適用していない。顔ありOK例外は動画ごとに確認）
- [ ] 同一素材を複数カットで使う場合、連続して見せる箇所は後続カットのtinを続き時間にした（毎回同じ開始秒に戻していない）
- [ ] 中間素材（スロー化・holdpad・再生成音声・CTA素材）を intermediates/ 等に保存した（消していない）

## C. 検品（「直した」と言う前に、必ず出力物から実測・目視）

- [ ] **修正 → 出力再生成 → 出力ファイルから実測/目視 → 報告** の順で行った（修正コードを書いた時点で「直した」と言っていない）
- [ ] **指摘秒だけでなく前後**を見た（例: 10-12s指摘なら 9.5/10.5/11.5/12.5/13.5。カットの入り・終わり・次カットへの戻り）
- [ ] **1フレーム問題は高密度**（1秒48分割相当の連続フレーム）で確認した。コンタクトシートだけで判断していない
- [ ] 音声は波形だけでなく**実聴**した（冒頭欠け・語尾切れ・吐息・無音・二重発話・食い込み）
- [ ] CTAは「冒頭」「言い切り」「前セリフとの食い込み」の3点を確認した
- [ ] BGMは他動画と同じ曲・同じ入り位置・同じ質感かを確認した
- [ ] **回帰チェック**: 過去合格済みの修正が戻っていないか、差分表の全項目を確認した
- [ ] 全セグメント・最終出力の音声ストリーム存在を ffprobe で確認した（concat無音化バグ対策）
- [ ] 要求仕様（話速・音量・尺等）があるものは**実測値**を取り、独立検査（別フォーク/外部AI、明示許容帯付き）を通した。**サブエージェント/外部AIの報告値は納品ファイルで親が再実測**した
- [ ] 検品証跡（フレーム・実測ログ）を qa/<動画ID>_v<NN>/ に保存した
