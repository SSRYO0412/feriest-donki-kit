## Q1. 時間の骨格は誰か（最重要・工程順が変わる）

**「この動画の時間を決めるのは何か」を最初に確定する。** 現行パイプラインの
[1]音声正本→[1.5]台本化→[2]構成設計 は (a) 専用の順序であり、(b)(c) では変わる。

| | (a) footage-first | (b) script-first | (c) reference-first |
|---|---|---|---|
| 骨格 | 収録された発話 | 台本・コンテ＋生成VO | 参考のタイムライン |
| 該当 | 型A/D（インタビュー・フリートーク・演者収録） | 型B/C（広告・商品紹介・faceless） | +C 完全転写（参考prproj移植） |
| 工程順 | [1]音声正本 → [1.5]台本化 → [2]選定 | 台本検算 → **★VO生成を先に確定** → 素材当て → 組立 | 参考実測が骨格 → 素材・テロップ移植 → VOを骨格に嵌める |
| 実例 | オリオン18/19 | VERARUS（canon 19条「VO先行への転換」はユーザー発案で確立した正） | Feriest 0801（参考うどん337Fへ移植） |

**(b) の鉄則 — VO先行**: 台本が骨格の案件で絵を先に組むと、VO生成後に話速retime地獄
（telop-pace-volume-method の全行一律retime）が構造的に発生する。**VOを先に確定し、
その実尺に絵を当てる**（VERARUSで学習済みの正解を工程として固定）。

**(c) の鉄則 — 構築前モーラ/秒検算ゲート**: 参考タイムラインが骨格（絵が先・尺固定）の
案件だけが「VO後嵌め」を正当化できる。その場合、**構築前に**コンテ/台本の全行を
fugashi でモーラ数化し、`行モーラ ÷ 目標モーラ/秒（参考実測）≦ スロット尺` を機械照合する。
収まらない行は**構築前に**ユーザーへ提示（文言はコンテ確定で変えられない案件が多い＝
分割・尺調整・ナレ省略の判断は先に取る）。話速の単位は字/秒でなく**モーラ/秒**
（漢字比率で字/秒は揺れる・feedback_japanese_speech_rate_mora）。

## Q3. 素材リスク → STRICT を事前判定（指摘を待たない）

従来の STRICT-USABILITY-SPANS / STRICT-SELECTION は「使えないカット混入の指摘が出たら
次周から」＝**必ず一度失敗してから発動する設計**だった。判定指標は素材だけから機械で
計算できるので、**インジェスト時に先に測って提案する**:

- 手持ち撮影・撮影間の移動が多い素材群 → transit 分節比率・「フローばらつき大∧カメラ移動大」
  同時成立の窓比率を全素材で計測
- 閾値超え（目安: transit相当が全窓の15%超・または手持ち率が高いと分かっている）なら
  **初回から STRICT モードを提案**（発動はユーザー承認。予算カードに工数影響を明記）
- ユーザー正解セットが既にある案件（過去指摘あり）は無条件で STRICT

## Q4. 量産形態 → QCプロファイル（黙って削る誘因を消す）

G00〜G80 フル＋Codex3対象＋合議採点を30本量産の全本に掛けるのは実行不能で、
実行不能なルールは黙殺される（9項目の真因）。削り方を**事前にユーザー承認された
正規プロファイル**にする。詳細と数値は short-video-qc SKILL「QCプロファイル」節が正本。

| プロファイル | 適用 | 内容 |
|---|---|---|
| FULL | 初号機・新様式・納品前最終 | G00〜G80 全部 |
| DELTA | シリーズ2本目以降 | 機械ゲート全数＋変更点まわりのみ全数目視＋N本に1本の抜き取りFULL |
| TRIAL | 社内試作 | 機械ゲート＋G19視聴のみ。**「納品不可」ラベル固定** |

選択は開始時にユーザー承認し gates.json `qc_profile` に記録（黙殺でなく契約）。
**三大禁止は全プロファイル共通で有効**（プロファイルは範囲の契約であり工程スキップではない）。

## 型C — コンテ×物撮り×生成VO×Premiere（2026-08-10 新設・Feriest 0801 から抽象化）

型A/D/B のどれでもない第4の型。字コンテ確定（文言を変えられない）・物撮り素材・
クローン/生成VO・Premiere+MOGRT・参考prproj 移植、が揃う商品紹介広告。
ノード雛形: `nodes-typeC.template.json`。工程列:

## 役割ベース抽象（配布対応・Q2〜Q4 と直交）

工程が要求する能力は**役割**で書き、実装（backend）は project.json `roles` で指定する。
その環境に無いツールは代替へフォールバックし、**どの役割も埋まらない工程は
「実行不能」を宣言して止まる**（黙って省く経路を作らない・9項目 item 4）。

| 役割 | 何をするか | backend の例（優先順） |
|---|---|---|
| 視聴役 | 動画を通しで観て違和感を列挙（G19） | agy → Gemini API → 人 |
| 敵対役 | 制作文脈なしで落とす理由を探す | Codex CLI (gpt-5.5) → 別フォークClaude → 人 |
| 採点役 | 独立採点・合議 | 採点サブエージェント×敵対役の2者 |
| 機械役 | 実測・全数列挙・突合 | ローカル python/ffmpeg（必須・代替なし） |
