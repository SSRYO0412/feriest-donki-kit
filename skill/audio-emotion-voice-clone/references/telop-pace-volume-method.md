# テロップ話速「早い/遅い」・音量・フォントサイズ修正の恒久手法（汎用版）

> 正本: `core/vo/references/telop-pace-volume-method.md`（sync_core.sh で配布）。
> ナレーション付き映像広告全般に適用。VERARUS 0284 の実修正（2026-07-10）で確立した手法の一般化。
> 由来の教訓: フラグ行だけを非フラグ行の中央値に合わせても「均一にはなったが全体が早い」と言われる。
> **行単位の均一性と、動画全体のテンポへの感覚的評価は別軸**。さらに目標値は計算で一発確定できず、
> 反復して初めて合う（実例: 中央値5.66→5.7"まだ早い"→5.0"ちょい遅い"→5.3で確定）。

## 話速「早い/遅い」の修正手順

1. **フラグ行だけでなく、動画内の全ナレーション行を対象に一律retimeする**。動画1本＝1つの目標字/秒で全行を統一する（1行だけ基準合わせすると動画全体のテンポがズレて「まだ早い/遅い」と感じられる）。
2. **目標字/秒は数式で決め打ちしない**:
   - 初期値 = その動画の非フラグ行の実測字/秒の**中央値**
   - レンダー → ユーザーに実際に再生してもらう → フィードバック（早い/遅い/ちょうど良い）→ 目標を**0.3〜0.5字/秒刻み**で調整 → 再レンダー、を「ちょうど良い」まで繰り返す
3. **文字数はスペース（全角/半角とも）を除いて数える**（管理DBの字数規約と一致させる。含めるとtempo計算がズレる）。
4. atempoは原則decel-only（遅くする方向のみ）で行を伸縮。
5. **話速変更で行の尺が変わったら、該当カットのdurにも反映**し、後続カット・CTAの累積オフセットを再計算する（音声とカット尺は別管理のため、両方揃えないとズレる）。

## 音量均一化（全行対象、フラグの有無を問わない）

1. 各行の音量を ffmpeg `astats` の **Overall RMS** で実測する。
   - ★`metadata=1:reset=1`は使わない（集計行=Overallが出なくなる）。
2. 動画内の外れ値行を、動画内の他行に合わせて `volume={gain}dB` で補正する。
3. **モノラル音源を`-ac 2`でステレオ化すると、電力保存処理で絶対値が一律ズレることがある**（全行が同じだけ下がる）。実害はないので、**相対的な行間差の均一性（標準偏差/レンジ）で判定**する。絶対値は最終ミックス後の ebur128（統合ラウドネス）で規定帯に収まっているかを見る。

## フォントサイズ「小さい/大きい」

- ビルドハーネスの `build_video()` に `font_size_overrides={sid: fontsize}`（後方互換の追加引数）を渡し、**該当カットだけ**変更する（`compilation/scripts/build_compilation.py` は対応済み）。
- 目視で周辺カットと比較し、画面からはみ出さない範囲で調整する。

## 運用（バージョン管理）

- 修正は必ず**新規v**（既存ファイル・既存pyは上書きしない。VERSIONING.md）。
- ユーザー承認後に、行単位の管理DB（テロップチェックDB等: 字/秒・文字数・表示秒数・元py・ステータス・修正メモ）と動画台帳（採用MP4/採用py/採用v）を更新する。
- 提出前に要求仕様（字/秒・音量）を**納品ファイルから実測**し、外部AI独立検査（明示許容帯付き）を通す。
