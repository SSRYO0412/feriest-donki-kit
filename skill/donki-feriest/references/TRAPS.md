# この案件で実際に踏んだ罠

★★は複数回踏んだ・時間を最も溶かしたもの。

---

## 1. Premiere / MOGRT の API

| 罠 | 中身 |
|---|---|
| ★★**強調は出現アニメが無いと発火しない** | `出現の型=なし` だと `強調の出方` を何にしても1pxも動かない。`強調の遅れ` は**出現アニメが終わってからの秒数** |
| ★**出方=0 は静的・1以上はアニメのみ** | 静的に大きくしたいなら0、動かしたいなら1以上＋出現アニメ |
| **強調の振幅** | 大きさ25では30fpsで**1フレームしか動かない**。40〜60で10〜27フレーム動く |
| ★★**`縦横比を固定=true` でプロパティ名が変わる** | `スケール (高さ)` → **`スケール`**（`スケール (幅)` は空文字の名前になる）。片方しか見ない検算が**3カットを「キーなし」と誤判定**した |
| ★**MOGRT の素材長は150F（5.000秒）** | 超えて `clip.end` で伸ばすと描画されない。**読み戻しでは気づけない**（クリップは0-337Fに見える）。複数枚を隙間なく敷き詰める |
| ★**`importMGT` で置き直すとモーションの「位置」が既定に戻る** | ロックアップが中央へずれ、👇画像だけ元位置に残って「※」に重なった |
| ★**クリップ差し替えで隣の頭を2F侵す** | 余白（+2F）を付けて置くため。戻すと**キーが inPoint から-2Fずれる** → 毎回打ち直す |
| **キーフレームは `inPoint` 基準** | 静止画の inPoint は約3600秒。`OFF = clip.inPoint.seconds` を足す |
| **`app.newProject` は返らないことがある** | ダイアログで止まりブリッジがコマンドを消費しなくなる。**タイムアウト＝失敗ではない**（プロジェクトは出来ていた）。二度実行せずまず「開いているか」を読む |
| ★**`app.project` は手前のプロジェクトを返す** | 実際に**参考うどん側に書き出してしまった**事故あり。**プロジェクト名＋シーケンス名＋クリップ枚数の3点照合**で中断させる |
| **項目探索は名前でなくパスで** | 版が変わってもファイル名は同じ。`getMediaPath()` で照合 |
| **QE はアクティブなプロジェクトしか見えない** | `proj.openSequence(seq.sequenceID)` でアクティブ化してから使う |
| **QE の `numItems` は Empty も数える** | `type==="Clip"` だけ集めてから添字を使う |
| **`importFiles` は非同期** | 呼んだ直後に探しても見つからない。スクリプトを分ける |
| **ExtendScript は ES3** | `forEach` が無い。トップレベル `return` は構文エラー（`pr.sh` が包むので末尾は `return <式>;`） |
| **CEP Bridge は毎セッション手動で Start** | 止まると外部から再開できない。未消費 `command-*.json` が溜まったら**再開前に消す** |
| **出力の拡張子はプリセットが上書きする** | `.mp4` を渡しても `.mov` で出る |
| **書き出しプリセット** | 「Mobile Device 1080p HD」は**横向きに強制する**。縦型は「Match Source - High bitrate」 |
| **Premiereのネイティブテキストは作れない** | ExtendScript / UXP / QE DOM いずれも不可（確定）。テロップは MOGRT 一択 |

## 2. 測定器の盲点（「効いていない」の8割はこれ）

| 事例 | 真相 |
|---|---|
| 「ロックアップが出ていない」 | 背景が白飛びしたピザで**白文字が埋もれていただけ**。c01では出ていた |
| 「テロップがはみ出し」 | **測定窓が狭かった**だけ。実際は2行化が効いていた |
| 「ズームが効いていない」 | 倍率の測定窓に**等倍のテロップ帯**を含めていた |
| 「テロップ色のマスクが全画面を検出」 | **背景の食材が同系色**。色マスクは汚染される |
| 「6カット中3カットがズーム未適用」 | **自分の検算のプロパティ名が間違っていた** |
| 「動く被写体の倍率が測れない」 | 内容が変わるのでスケールだけのモデルが当たらない（相関0.12〜0.73） |
| 「テロップが1行」と出た | 商品パッケージの白とピンクを拾って行が繋がっていた |

★**手順にすると**:
1. その測定器で**変化が出るはずの条件**を1つ作り、**実際に出ることを確かめる**
2. 出なければ**測定器を替える**
3. 配色・背景・不透明度など**見えなくしている要因**を潰す
4. そこまでやってから、はじめてアプリ側の非互換を疑う

★**裁定は拡大して目視。機械で測るなら、背景に無い色（フチ色 `#3C3934`）を手がかりにする。**

★**候補が複数あるときは診断物を1本作って1回で決着させる。**
（赤・特大・全文字・出現アニメ有りの「絶対に見えるはずの条件」を1本書き出して全フレーム測る）

## 3. 素材まわり

| 罠 | 中身 |
|---|---|
| ★**素材DBのラベルを信用しない** | `IMG_2852#w0003` は `person_count=0` だが実画に**素手の指**が写っていた |
| ★**向きの判定** | 原本は全て3840×2160で返るが**229本に rotation メタがあり実体は縦**。`probe` の w/h で判定すると全数「横」になる |
| ★**連番が商品をまたぐ** | `20260803_honma_a08xx.MP4` はフォルダ分けが撮影順と一致していない。**フォルダ名の商品帰属を信用しない** |
| **白飛びは相対で見る** | 「6.34%」は単体では判断できない。**他のショットが0.00%だから異常と分かる** |
| **丸い被写体×9:16** | ピザを縦画面に収めると必ず「中心がずれる／箱が見える」問題が出る。**素材ごとに被写体の中心位置を測って選ぶ** |
| **この素材群に「激しいカメラワーク」は無い** | 平行移動の実測最大が5.3px。「なめるような移動」（a0928）が上限 |

## 4. 選定の罠

| 罠 | 中身 |
|---|---|
| ★**別クリップでも「同じ絵」なら重複** | 平坦な表面接写を連続させない |
| ★**1案だけで決めない** | 3〜5候補をスコアリング。「変えない」も候補に入れる |
| ★**Codexの敵対レビューを必ず投げる** | 12ショット案に6点の指摘が出て**全て妥当**だった |
| **数値だけ合わせない** | cuts/分だけ参考に合わせるとテロップ密度を無視した過剰分割になる |
| **意味を回収しているか** | 「ぷりぷり♡トロトロ♡」に対しチーズ伸び3連打では「ぷりぷり」を映像で回収していない |

## 5. 運用

| 罠 | 中身 |
|---|---|
| ★**11DB体制**を無視して場当たりにDBを作った | テンプレを複製して使う |
| ★**修正台帳 ≠ 修正指示DB** | 修正台帳はカット台帳をもとに作る記入用シート |
| **`notion-update-data-source` の select 選択肢の変更が API から一切反映されない**（このワークスペース） | 正規語彙へマッピングし、原文は「備考」に保全する |
| **誤って作った器は削除せずリネームで残す** | `【重複・使用しない／正本=…】` |
| ★**ブートディスクが満杯になる** | 実際に ENOSPC でスクリプトの書き込みが失敗した。一時ファイルはSSD側へ |
| **並列を上げすぎると ExFAT マウントが落ちる** | par15 を超えない |

## 6. 一度失敗した「やってはいけない」10箇条

1. **案件の引き継ぎ書を読まずに着手する** → フォントを誤断定して後退させた
2. **「無い」と判断する前に案件側を確認しない** → 同上
3. **参考のテロップを1枚だけ見て様式を決める** → 6枚全部同じ書式で作り直しになった
4. **素材DBのラベルを信用する** → `person_count=0` なのに素手が写っていた
5. **テロップの色を素材の地色から採る** → 背景と同化して読めなくなった
6. **cuts/分だけを参考に合わせる** → テロップ密度を無視した過剰分割になった
7. **同じAPIで書いて同じAPIで読む検算だけで「できた」と言う** → 座標系の誤りを原理的に検出できない
8. **自分の検算のプロパティ名を疑わない** → 3カットを誤判定した
9. **カット選定を1案だけで決める** → 3〜5候補＋Codex敵対レビューが必須
10. **`app.project` を信じる** → 別プロジェクトに書き出す事故
