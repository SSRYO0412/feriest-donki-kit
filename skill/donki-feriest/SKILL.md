# donki-feriest — ドン・キホーテ（Feriest）案件 専用スキル

> **これは案件固有スキル**です。汎用の手順は `video-ops` / `short-video-pipeline` /
> `premiere-bridge-ops` / `short-telop-craft` にあります。ここには
> **この案件でしか通用しない確定値と、この案件で実際に踏んだ罠**だけを置いています。
>
> 実体は SSD 側 `/Volumes/Extreme SSD/FERIEST/_skill/donki-feriest/`。
> **SSDを渡せばこのスキルごと移動します。**

## 作業の型（この案件の標準フロー）

```
[0] 修正台帳から未対応の「修正指示」を引く
     ↓
[1] 実測してから動く（推測で直さない）
     - 「白飛び」→ 全カットの輝度≥250画素比を測って比較する
     - 「テンポ」→ ショット尺の分布と cuts/分 を出す
     - 「カメラワーク」→ 実素材のフレーム間差を測る
     - 「色が埋もれる」→ 背景平均色との ΔRGB を出す（参考の帯 93〜142）
     ↓
[2] カットを変えるなら 3〜5候補をスコアリング（内容一致45/寄り引き15/新鮮さ15/尺10/画質5/NG-100）
     「変えない」も候補に入れる。全候補を実画で目視（DBのラベルを信用しない）
     ↓
[3] ★Codex(gpt-5.5)に敵対的レビューを投げる（CUT-QC-RULES 手順5）
     ↓
[4] Premiere で実装 → 全ショットの機械検算
     ↓
[5] 完成画素で検証（読み戻しだけで「できた」と言わない）
     ↓
[6] Notion に記録（修正台帳の行 ＋ Feriest 修正記録DB に1行）
```

## 毎回やる機械検算（全部0件が正常）

```
V1の隙間/重なり ・ 同一素材同一区間の重複 ・ 全トラックの終端ずれ
MOGRTの fontTextRunLength 不一致 ・ ズームキーの inPoint 頭ズレ
設計カット点で画が変わらない ・ 設計外の画変わり
白飛び2%超のショット ・ 黒フレーム ・ 0.40秒未満のショット
```

★**差し替えのたびに「隣のクリップの頭を2F侵す」現象が起きます。** 毎回検算して戻し、
戻したらそのクリップのズームキーを inPoint 基準で打ち直す。

## やってはいけない

- ★`.prproj` の**コピーを開く**（documentIDが複製されシーケンスが合流する）
- ★**コンテの文言を変える**（一字も）

- py・prproj・jsx を**上書きする**（必ず新版・却下版も残す）
- 完成MP4を**直接編集する**
- 検証目的だけの書き出しを**ユーザーに渡す**（目視の最終判断はユーザーがする）
